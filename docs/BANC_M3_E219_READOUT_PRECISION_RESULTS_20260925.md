# E219 결과: 입력 스키마 오류로 계산 전 중단

E219는 유효한 비교 결과를 만들지 못했다. 원본 프로세스 1회가 checkpoint의 motor ID를 `adapter.parameters.motor_ids`에서 읽으려다 KeyError로 끝났다. 실제 저장 위치는 `adapter.calibration.motor_ids`다. 입력 로드 후 여섯 readout 계산 전 실패했으므로 계산 수는 0이고 raw profile도 없다. 목표·적합·보행 성능에 대한 새 결론은 없다.

부모 FIRST는 Windows CRLF 변환에 따른 manifest 해시 오류를 발견했고, 같은 실제 gpt-6-sol/medium이 정확한 바이트 저장으로 첫 수정했다. 부모 SECOND의 순수 테스트 5개와 Ruff는 통과했지만, 부모와 생성 fixture 모두 실제 checkpoint ID 경로를 놓쳤다. 이 실패를 통과로 취급하지 않는다. 원본 재시도는 0이며 기존 소스·freeze·실패 파일을 보존한다. 사용자 지정 절차에 따라 남은 경로 오류는 부모가 E220 복구 구현에서 수정한다.

원본 감독 시간 1.8060182999906829초, 내부 실패 시점 0.8440000000118744초, 최대 단일 프로세스 RSS 302804992bytes, 최대 관찰 합산 RSS 277041152bytes, 출력 1127bytes. 종료되지 않은 소유 프로세스와 강제 종료는 0이다. 누적 원본 프로세스 시간은 5791.716809299691/6004초, 잔여 212.2831907003092초다. 부모 순수 검사는 1.3746635999996215초, 정적 hash 검사는 0.14387040000292473초, 줄바꿈 재현은 0.004224599993904121초였으며 그 외 준비·설계·agent 사고 비용은 미측정이다.

별도 E220은 동일 입력·여섯 profile·dtype·한계·판정을 유지하고 ID 로딩만 올바르게 연결한다. 새 반응 탐색이나 학습이 아니며 E219 비용을 포함한 잔여 자원에서 사전 예약한다. E150 최선 물리 기록, M2, UI, F6 미노출과 F1–F8 미완료 상태를 유지한다.
