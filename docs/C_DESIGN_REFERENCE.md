# 1. C의 목표를 먼저 고정하기

## 기본 구성

제가 권하는 첫 C의 구성은 다음과 같습니다.

> **FlyWire FAFB v783 전뇌 연결망 + 연속적인 신경 상태 계산 + 검토된 감각·운동 연결 + 기존 B의 NeuroMechFly 보행 물리 + 실시간 모니터링**

여기서 “전뇌”는 **선택한 데이터 스냅샷에 포함된 뇌 전체를 계산한다**는 뜻입니다. 전신 신경계, 모든 감각기관, 실제 근육 신경지배까지 완전히 복원했다는 뜻은 아닙니다.

현재 B fix_2는 C 개발의 기준선으로 사용할 수 있습니다. 다만 기존 재평가가 확인한 것은 사용자 물리 기록의 일관성과 개선된 판정의 통과이며, fix_2로 새로운 물리 실험을 실행했다는 의미는 아니었습니다. C에서 신경 계산과 몸의 연결을 바꾸면 **C 구성으로 다시 검증해야 합니다.**  

## C에서 구현할 것과 나중으로 미룰 것

| 첫 C의 필수 범위 | 별도 후속 확장 |
|---|---|
| 선언된 전뇌 스냅샷의 모든 포함 뉴런 계산 | 실제 복측신경삭 전체와 근육 제어 회로 |
| 실제 화학 연결망에 기반한 신호 전파 | 수용체·신경조절·구획별 정밀 생물물리 |
| 환경 관측을 실제 뉴런 ID에 연결 | 실제 복안에 가까운 영상 처리 |
| 실제 하행 뉴런 집단의 출력으로 보행 제어 | 날개 공기역학을 포함한 비행 |
| 뉴런·영역별 활성도와 개입 모니터링 | 학습, STDP, 강화학습, JEPA |
| 저장·복원·대조 실험·성능 측정 | 공간 지도·SLAM·다단계 계획 |

**전체 뇌를 계산하게 만드는 것과, 그 모델에서 안정적인 탐색이 나타나는 것은 서로 다른 개발 목표입니다.** 이것을 하나로 묶으면, 움직이지 않을 때 무엇이 잘못됐는지 구분하기 어려워집니다.

따라서 완료 상태도 최소한 다음처럼 분리합니다.

```text
데이터 검증 완료
    ↓
전뇌 신경 계산 검증 완료
    ↓
감각·운동 연결 검증 완료
    ↓
실제 몸과의 폐루프 검증 완료
    ↓
개별 생물학적 실험의 재현 여부 평가
```

첫 단계가 성공했다고 마지막 단계까지 성공했다고 표시하지 않습니다.

# 3. 전뇌 데이터 설계

## 3.1 첫 데이터셋은 FAFB v783로 고정

초기 C에서는 **FAFB v783 하나로 시작**하는 것을 권합니다. 현재 공식 Codex 문서는 FAFB v783과 BANC v888 등의 정적 자료를 구분해 제공하며, 데이터 다운로드와 주석 버전도 별도로 다룹니다. citeturn981553view0

BANC는 뇌와 신경삭을 함께 다룬다는 장점이 있지만, lamina와 ocellar 계열 등 일부 구조의 결측이 보고되어 있습니다. 따라서 나중에 BANC로 전환하더라도 단순히 데이터 파일만 교체하는 것이 아니라 **감각 경계와 운동 경계를 다시 정의하는 작업**으로 보아야 합니다. citeturn508464search6

초기 단계부터 FAFB·BANC·MANC 등을 한 연결망에 섞지는 않습니다.

**다른 개체의 같은 세포형은 대응 후보이지, 동일한 뉴런이 아닙니다.**

## 3.2 “약 14만 개”를 코드에 하드코딩하지 않기

배열 크기는 실제로 내려받은 데이터에서 결정합니다.

```text
원본 뉴런 목록 수
검증 대상으로 포함한 뉴런 수
실제로 계산하는 뉴런 수
명시적으로 제외한 뉴런 수

원본 연결 행 수
해부학적 시냅스 접촉 수
뉴런 쌍으로 집계한 연결 수
실제 동역학에 사용하는 연결 수
```

이 숫자들은 서로 다릅니다.

특히 **시냅스 접촉 수와 계산용 연결 수를 혼동하면 메모리 예상부터 잘못됩니다.**

## 3.3 데이터 처리 순서

```text
공식 원자료 확보
    ↓
파일 해시·스키마 검사
    ↓
전체 뉴런 master table 생성
    ↓
세포형·영역·좌우·전달물질 주석 결합
    ↓
연결 집계 및 제외 정책 적용
    ↓
모델 가중치 생성
    ↓
희소 배열 생성
    ↓
불변식 검사
    ↓
완성된 데이터 bundle 공개
```

여기서 **뉴런 목록은 연결의 양 끝점만 모아서 만들면 안 됩니다.** 그렇게 하면 연결이 없거나 선택한 연결 파일에서 빠진 뉴런이 사라질 수 있습니다.

연결 집계도 주의해야 합니다. 같은 뉴런 쌍이 여러 영역에 걸쳐 있으면 여러 행이 나올 수 있지만, 전체 합계 행과 영역별 행을 모두 더하면 중복 집계입니다. 공식 Codex 문서도 영역별 복수 연결 행과 데이터별 연결 임계값을 구분합니다. citeturn981553view0

## 3.5 ID와 좌우 방향은 특히 엄격하게 처리

외부 ID는 다음과 같은 문자열 이름공간을 사용합니다.

```text
flywire:fafb:783:<root_id>
hemibrain:<body_id>
model:<auxiliary_node_id>
```

내부 계산에는 별도의 정수 인덱스를 사용합니다. 브라우저와 JSON에서는 긴 root ID를 숫자로 변환하지 않습니다.

또 하나 중요한 문제는 **FAFB의 좌우 반전 이력**입니다. 공식 FAQ는 주석의 좌우는 수정했지만 영상과 분할 데이터는 그대로라고 설명합니다. 따라서 화면 좌표의 왼쪽, 뉴런의 soma-side, 실제 출력이 향하는 쪽을 동일시하면 안 됩니다. citeturn981553view0

C에서는 최소한 다음을 별도로 저장합니다.

```text
생물학적 세포체 측
생물학적 출력 투사 측
원본 영상의 좌우 규약
주석 버전의 좌우 규약
뇌 지도 표시 변환
몸 좌표계 변환
```

**“이름에 L이 있으니 왼쪽 다리 구동에 연결한다”는 구현은 금지하는 편이 맞습니다.**

# 4. 신경 계산 모델

## 4.1 CPU 기준 모델과 GPU 모델을 함께 설계

처음부터 GPU 코드 하나만 만들지 않는 것이 좋습니다.

| 계산기 | 목적 |
|---|---|
| `legacy_b_rate` | 기존 B와 동일한 회귀 기준선 |
| `exp_lif_cpu_reference` | 방정식과 이벤트 순서를 확인할 기준 구현 |
| `exp_lif_cuda` | 같은 모델을 GPU에서 계산 |

전뇌 LIF 모델은 실제 연구 사례가 있습니다. Shiu 등의 연구는 연결망과 전달물질 추정을 이용한 모델로 특정 감각–운동 반응을 시험했습니다. 다만 그 결과가 새로운 환경에서의 자유 보행을 자동으로 보장하지는 않습니다. citeturn981553view1

## 4.2 권장 시작 모델

초기 C에서는 **누설 적분–발화 모델과 지수 감쇠 시냅스 상태**를 사용합니다.

\[
\tau_m\frac{dv_i}{dt}
=
E_L-v_i+h_i+x_i
\]

\[
\frac{dh_i}{dt}
=
-\frac{h_i}{\tau_s}
\]

지연된 presynaptic spike가 도착하면,

\[
h_i \leftarrow h_i+w_{ij}
\]

로 갱신합니다.

여기서 \(h_i\)는 이 설계에서 **mV 단위의 시냅스 구동 상태**입니다. 전도도라고 부르지 않습니다. 전도도 기반 모델로 바꾸려면 reversal potential과 단위를 포함한 별도 방정식이 필요합니다.

문헌 코드에서 참고할 수 있는 시작값은 다음과 같습니다.

| 항목 | 시작값 예시 |
|---|---:|
| 휴지막·리셋 전압 | −52 mV |
| 발화 임계값 | −45 mV |
| 막 시간상수 | 20 ms |
| 시냅스 시간상수 | 5 ms |
| 불응기 | 2.2 ms |
| 전달 지연 | 1.8 ms |
| 연결량 1당 가중치 배율 | 0.275 mV |

이는 해당 연구의 **모델 파라미터**이며 각 뉴런에서 측정한 값이 아닙니다. 

중요한 것은 숫자만 가져오는 것이 아니라, **발화 판정·리셋·불응기·지연 이벤트의 처리 순서까지 모델 정의에 포함하는 것**입니다.

예를 들어 초기 C에서는 불응기 동안 전압은 리셋값에 고정하되 시냅스 상태의 감쇠와 유입은 계속되도록 정의할 수 있습니다. 이 규칙이 원본 연구 코드와 다르면 **“Shiu 모델의 정확한 재현”이 아니라 “문헌에서 시작값을 참고한 C 모델”**로 표시해야 합니다.

## 4.3 가중치와 전달물질

B의 다음 규칙을 전뇌에 그대로 적용하지 않습니다.

```text
모든 실제 연결을 양수로 처리
연결량에 제곱근 적용
수신 뉴런별로 정규화
```

초기 전뇌 가중치는 다음처럼 분리합니다.

\[
w_{ij}
=
\text{count}_{ij}
\times
\text{unit weight}
\times
\text{sign}_{ij}
\]

`count`는 원자료에 남기고, `weight`는 모델 파라미터로 별도 저장합니다.

또한 **초파리의 glutamate를 무조건 흥분성으로 처리하면 안 됩니다.** Shiu 모델은 GABA와 glutamate를 억제성으로 가정하며, 논문은 실제 glutamate 작용이 연결에 따라 달라질 수 있다는 한계도 명시합니다. citeturn210739view2

전달물질을 모르는 연결은 별도 정책이 필요합니다. 엄격한 프로파일에서는 미확정 문제를 해결하기 전 승인하지 않고, 탐색용으로 효력을 0으로 둘 경우에도 **“해부학적 연결은 존재하지만 모델에서 가린 연결”**로 개수를 공개합니다.

## 4.4 정확한 계산 순서

각 신경 tick에서는 다음 순서를 고정합니다.

```text
예약된 시냅스 도착·외부 입력 적용
    ↓
막전위와 시냅스 상태 적분
    ↓
불응기가 아닌 뉴런의 발화 판정
    ↓
스파이크 시각 기록
    ↓
출력 이벤트를 미래 지연 큐에 예약
    ↓
리셋·불응기·발화율 필터 갱신
```

CPU와 GPU가 이 순서를 동일하게 사용해야 합니다.

**전압 오차가 작다고 스파이크까지 동일하다는 뜻은 아닙니다.** 임계값 근처에서는 작은 수치 차이가 발화 시각을 바꿀 수 있으므로, 전압과 스파이크 시각을 별도로 검사합니다.

# 5. 가장 중요한 부분: 감각과 전뇌를 어떻게 연결할 것인가?

전뇌 데이터만 넣었는데 움직이지 않는 경우, 연결망 자체보다 **감각 입력과 운동 출력의 경계가 잘못됐을 가능성**부터 분리해서 확인해야 합니다.

## 5.1 기존 B 센서를 재사용하되, 의미를 과장하지 않기

초기 C는 B의 다음 관측을 재사용할 수 있습니다.

```text
64방향 시각 표식 관측
9방향 근접 거리
좌우 냄새 농도
접촉
자기 회전 관측
```

하지만 이것은 복안과 말초 감각계를 그대로 복원한 신호가 아닙니다. 기존 B 문서도 광선 관측과 이상화된 감각이라는 한계를 명시합니다. fileciteturn35file1L268-L274

따라서 중간에 **SensoryEncoder**를 둡니다.

```text
센서 채널
    ↓
정규화·시간 필터·특징 추출
    ↓
검토된 실제 뉴런 ID 집합
    ↓
mV 입력 또는 Hz 단위의 확률 입력
```

## 5.2 입력 매핑은 독립적인 파일로 관리

각 입력 채널은 다음 정보를 가져야 합니다.

| 항목 | 예 |
|---|---|
| 관측 채널 | 좌측 냄새 농도, 방향성 밝기 변화 |
| 실제 대상 | 해소된 root ID 목록 |
| 선정 근거 | 세포형·영역·공식 주석·논문 |
| 적용 경계 | 감각뉴런, 초기 중계뉴런, 실험적 직접 주입 |
| 변환 방식 | 구동 전압, Poisson 입력 |
| 파라미터 | gain, baseline, cap, delay |
| 불확실성 | 검증됨·추정·공학적 매핑 |
| 버전 | 데이터·주석·매핑 해시 |

대상 뉴런이 검색되지 않으면 **`BLOCKED_PORT_BINDING`으로 중단**합니다.

실제 ID를 찾지 못했다고 가짜 뉴런을 만들거나 B의 HD 노드로 자동 대체하지 않습니다.

## 5.3 세 가지 입력 조건을 구분

**정상 감각 연결:** 환경 관측이 검토된 감각·중계 뉴런으로 들어갑니다.

**실험적 직접 주입:** EPG나 하행 뉴런 등에 직접 자극을 넣어 회로를 검사합니다. 이것을 자연 감각 처리 성공으로 해석하지 않습니다.

**보조 입력:** B의 HD·GOAL 계산 결과를 넣는 비교 조건입니다. 전뇌 내부에서 방향 추정이 자연 발생했다는 근거로 쓰지 않습니다.

이 구분이 없으면 “정답 방향을 EPG에 입력해 놓고 전뇌가 방향을 알아냈다”고 잘못 판단할 수 있습니다.

## 5.4 나중에 실제 영상으로 확장할 때

FlyGym 카메라나 `flyvis`를 결합할 수 있도록 포트는 열어 두되, 처음부터 필수로 묶지는 않습니다. `flyvis`는 연결 제약과 과제 학습을 결합한 별도의 시각 모델입니다. citeturn289340search0

외부 시각 모델을 결합할 때는 **어느 영역을 외부 모델이 담당하는지 명확히 지정**해야 합니다.

같은 시각 뉴런을 내부 LIF에서 계산하면서 외부 모델의 동일한 결과를 다시 넣으면, 같은 회로를 두 번 계산하는 문제가 생깁니다.

# 6. 전뇌 출력으로 몸을 움직이게 하기

## 6.1 뉴런에서 관절로 바로 연결하지 않기

초기 C의 출력 경로는 다음과 같습니다.

```text
실제 하행 뉴런 집단의 발화율
    ↓
MotorDecoder
    ↓
전진·후진·회전 요청
    ↓
기존 B의 좌우 보행 구동 변환
    ↓
HybridTurningController
    ↓
42개 관절과 발 접착
```

즉, **C에서도 B의 저수준 CPG·접촉 보정은 남습니다.** 전체 VNC를 구현하지 않았으므로 그 부분까지 전뇌가 생물학적으로 재현했다고 주장하지 않습니다.

## 6.2 조향 출력 후보

좌우 DNa02 집단은 조향 readout의 문헌 기반 후보로 삼을 수 있습니다. PFL3·PFL2와 하행 뉴런을 연결해 목표 방향에 대한 조향을 설명하는 연구가 있습니다. citeturn454353search0

초기 디코더는 다음과 같이 작게 둡니다.

\[
u_{\mathrm{yaw}}
=
\operatorname{clip}
\left(
k_{\mathrm{turn}}(r_R-r_L),
-u_{\max},u_{\max}
\right)
\]

전진·후진도 검토한 출력 집단의 발화율로 계산합니다.

\[
u_{\mathrm{speed}}
=
\operatorname{clip}
\left(
k_f r_{\mathrm{forward}}
-
k_b r_{\mathrm{backward}}
-
k_s r_{\mathrm{stop}},
-v_{\mathrm{back}},v_{\mathrm{forward}}
\right)
\]

이 식들은 **설계의 시작점**입니다. 실제 집단 선정과 gain은 별도 자극 실험으로 확인해야 합니다.

특히 전진용 출력 집단이 아직 확정되지 않았다면, 그 단계에서는 **조향 연결만 검증된 상태**로 표시해야 합니다. 근거 없는 root ID를 설계서에 채워 넣는 것보다, 데이터 빌드 이후 반드시 해소해야 하는 조건으로 두는 것이 안전합니다.

디코더에는 영상·실제 좌표·정답 방향을 직접 입력하지 않습니다. 그런 정보를 받는 큰 신경망을 두면 실제 행동은 그 디코더가 만들어내고, 전뇌는 장식이 될 수 있습니다.

## 6.3 후진 복구 보조 제어를 반드시 분리

B의 후진 복구는 공학적인 보조 상태기에서 나옵니다. 기존 재평가도 이를 전뇌의 자발적 판단과 구분해야 한다고 지적했습니다. 

C에서는 다음 네 모드를 명시적으로 제공합니다.

| 모드 | 몸을 실제로 제어하는 것 | 용도 |
|---|---|---|
| **B_COMPAT** | 기존 B 제어기 | 회귀 기준선 |
| **C_SHADOW** | B가 몸을 제어하고 C는 관측만 받아 계산 | 데이터·신경 엔진 진단 |
| **C_ASSISTED** | C 출력 + 회피·후진 보조 | 공학적인 안정성 실험 |
| **C_STRICT** | C 출력, 회피·후진 보조 꺼짐 | 전뇌 제어 기여 평가 |

매 제어 시점에는 다음을 기록합니다.

```text
u_neural
u_assist
u_final
command_source
assist_reason
motor_coupled
```

**C가 제대로 출력하지 못할 때 B가 자동으로 대신 움직이는 동작은 넣지 않습니다.**

다만 수치 오류·넘어짐·영역 이탈·사용자 중지 시 **실험을 멈추는 안전 기능**은 유지합니다. 안전 정지와 몰래 방향을 수정하는 보조 제어는 다른 것입니다.

# 7. 신경·물리·화면의 시간 동기화

이 부분은 C에서 새로 꼼꼼하게 설계해야 합니다.

## 권장 시작 주기

| 계산 | 간격 |
|---|---:|
| 물리·저수준 보행 제어 | **0.1 ms** |
| LIF 신경 적분 | **0.1 ms** |
| 상위 운동 명령 | **5 ms** |
| 초기 단순 감각 관측 | **5 ms** |
| 후속 영상 입력 | **20 ms부터 검토** |
| 모니터링 전송 | **50 ms, 20 Hz** |
| 브라우저 렌더링 | 독립 |

물리 주기는 B에서 유지하는 값이며, 신경 적분 간격은 제안하는 시작값입니다. C의 신경 적분은 더 작은 간격과 비교해 수렴성을 확인해야 합니다. B는 현재 물리 0.1ms·상위 제어 5ms를 사용합니다. fileciteturn35file1L236-L245

## 미래 신경 출력으로 과거 몸을 움직이지 않기

제어 경계가 \(t_k\)라면 다음 순서로 처리합니다.

```text
1. t_k에 예약된 개입 적용

2. t_k의 몸에서 관측 O_k 생성

3. t_k까지 계산된 신경 상태에서 운동 명령 u_k 추출

4. 몸을 [t_k, t_k+5ms) 동안 u_k로 진행

5. 신경계도 같은 구간을 O_k를 입력으로 진행

6. 두 계산이 t_k+5ms에 도달한 뒤 기록·화면 상태 공개
```

이렇게 하면 새 관측이 신경 상태에 반영된 결과는 **다음 운동 구간부터** 영향을 줍니다.

반대로 신경을 먼저 5ms 진행한 뒤 그 결과를 이미 지난 몸의 5ms 구간에 적용하면 시간 관계가 틀어집니다.

이 결합 방식에는 제어 주기 하나에 해당하는 지연이 생길 수 있으므로, 이를 **`coupling_profile`에 명시하고 B 방식과 별도로 검증**합니다.

시간은 부동소수점 누적값보다 **정수 tick**을 기준으로 관리합니다. 성능이 부족하더라도 계산 tick을 건너뛰지 않고 모델 시간이 실제 시간보다 느리게 진행되도록 합니다.

# 8. GPU·메모리·실행 구조

## 8.1 희소 가중치, 밀집 뉴런 상태

전압·시냅스 상태·불응기 배열은 뉴런 수만큼 밀집 배열로 둡니다. 연결 가중치는 희소 구조를 사용합니다.

초기 기준은 **postsynaptic-major CSR**입니다.

```text
W[post, pre]

incoming = W @ presynaptic_spikes
```

이 방향을 명시하지 않으면 실제 연결을 전치해서 전파하는 버그가 생기기 쉽습니다.

GPU 버전에서는 상태·가중치·지연 큐를 GPU에 유지하고, 신경 하위 스텝마다 `.cpu()`, `.numpy()`, `.item()`을 호출하지 않도록 합니다. 5ms 경계에서 작은 하행 출력만 CPU로 가져오고, 선택한 모니터링 신호는 더 낮은 주기로 가져옵니다.

**처음부터 custom CUDA를 작성하기보다, CPU 기준 구현 → 일반 GPU 희소 구현 → 병목 측정 → 최적화 순서가 좋습니다.**

## 8.2 자원 예산 예시

다음은 **뉴런 14만 개, 뉴런 쌍 연결 1,000만 개를 가정한 계산**입니다. 실제 데이터 개수나 실행 벤치마크가 아닙니다.

| 자료구조 | 대략적 크기 |
|---|---:|
| 뉴런별 FP32 상태 8개 | 4.48 MB |
| CSR 인덱스와 가중치 | 약 81.1 MB |
| 연결별 16비트 지연을 별도 저장 | 20 MB |
| 20슬롯 × 전체 뉴런의 FP32 지연 버퍼 | 11.2 MB |
| 전체 뉴런 쌍의 FP32 **밀집** 행렬 | **78.4 GB** |

희소 기본 배열은 생각보다 작을 수 있습니다. 그러나 scratch buffer, 양방향 인덱스, Python 객체, 데이터 변환, 시각 모델, 체크포인트 복사본, 기록 버퍼는 별도입니다.

그리고 **메모리에 들어간다고 실시간으로 계산되는 것은 아닙니다.**

연결 1,000만 개를 0.1ms마다 모두 방문하면 모델 1초당 \(10^{11}\)개의 연결 기여를 처리하게 됩니다. 따라서 RTX 4080 16GB를 목표 장치로 잡더라도 실제 속도는 측정해야 합니다.

측정할 항목은 다음 정도면 충분합니다.

```text
전체 데이터 로딩 시간
CPU 최대 메모리 / GPU 최대 메모리
신경 계산 시간
물리 계산 시간
감각·출력 변환 시간
기록 시간
모델 시간 / 실제 시간 비율
```

## 8.3 프로세스는 처음에는 단순하게

초기에는 **하나의 simulation worker가 신경·몸·clock·RNG를 소유**하게 하는 것이 좋습니다. API 서버와 숫자 계산은 분리하되, 처음부터 여러 프로세스와 분산 RPC로 나누지는 않습니다.

대조군과 개입군도 기본적으로 다음처럼 **순차 실행**합니다.

```text
초기 체크포인트
    ├─ 대조군 실행·저장
    └─ 같은 초기 체크포인트 복원 → 개입군 실행·저장
```

전뇌 두 개를 동시에 메모리에 올릴 필요가 없고, 재현성 관리도 단순해집니다.

# 9. 모니터링과 통신

## 9.1 14만 개 타일을 만들지 않기

C 화면은 다음과 같이 바꿉니다.

**전체 보기:** 영역·세포형별 발화율과 상태 요약.

**검색:** root ID, 세포형, 영역, 출력 측, 전달물질.

**선택 뉴런:** 막전위, 발화 이벤트, 발화율.

**몸:** 관절·접촉·경로·개체 시점.

**인과성:** 감각 입력 시각, 신경 출력, 보조 출력, 최종 운동 명령.

**시스템:** 계산 범위, 실제 연결 수, dt, 메모리, SIM/WALL, 기록 누락·오류.

전뇌 연결 전체를 그래프 선으로 그리지 않습니다. 선택한 뉴런의 이웃 연결이나 특정 영역만 제한적으로 표시합니다.

뇌 좌표가 있는 뉴런은 점·밀도로 표현하고, 실제 신경돌기 형태는 선택한 소수만 불러옵니다. 도식 좌표를 실제 해부학 좌표로 표시하지 않습니다.

## 9.2 모든 값을 0~1로 만들지 않기

| 신호 | 표시 단위 |
|---|---|
| 막전위 | mV |
| 발화율 | Hz |
| 스파이크 | 발생 시각 |
| legacy 활성도 | 무차원 0~1 |
| 발 접촉력 | BW 또는 명시한 물리 단위 |
| 운동 요청 | mm/s, rad/s |

막전위 −52mV를 0~1 색상으로 시각화할 수는 있지만, **원시 저장값까지 0~1로 바꾸면 안 됩니다.** 색상 범위와 물리 단위는 분리합니다.

## 9.3 프로토콜 v3

제어 요청은 JSON, 신호 배열은 바이너리로 분리합니다.

```text
JSON:
초기화 / 시작 / 정지 / 카탈로그 검색 /
구독 변경 / 개입 예약 / 체크포인트 / 실험 비교

Binary:
선택 뉴런 전압 /
선택 뉴런 발화율 /
스파이크 이벤트 /
영역 요약
```

신호 프레임에는 다음이 필요합니다.

```text
sequence
subscription_epoch
start_tick
end_tick
dtype
channel_count
unit_descriptor
payload_bytes
```

구독 목록이 바뀌면 `subscription_epoch`를 바꾸어, 과거 프레임의 값이 새로운 뉴런 이름 아래 표시되지 않게 합니다.

화면 표시용 프레임은 밀리면 최신 것으로 교체할 수 있습니다. 하지만 **개입 명령과 과학적 기록은 조용히 버리면 안 됩니다.**

# 10. 기록·체크포인트·개입

## 10.1 전체 전압을 매 신경 스텝 저장하지 않기

뉴런 14만 개의 FP32 전압을 10kHz로 저장하면 **초당 5.6GB**입니다.

따라서 기본 기록은 다음처럼 나눕니다.

| 기록 | 제안 기본값 |
|---|---|
| 몸·운동·접촉·과제 이벤트 | 10Hz 이상 |
| 선택 뉴런 전압 | 100Hz |
| 선택 뉴런 발화율 | 20~100Hz |
| 영역 요약 | 10Hz |
| 전체 전압 스냅샷 | 기본 꺼짐, 진단 시 0.2~1Hz |
| 전체 스파이크 | 선택적 기록, 용량 예측 표시 |

스파이크도 무조건 작지는 않습니다. 예를 들어 뉴런 14만 개가 평균 10Hz로 발화하고 이벤트당 12바이트를 쓴다는 가정이면, 압축 전 기록은 **시간당 약 60.5GB**입니다.

초기 저장 형식은 **NPY 청크 + JSONL 이벤트 + manifest**로도 충분합니다. 대용량 저장 라이브러리는 나중에 교체할 수 있도록 `Recorder` 인터페이스를 분리합니다.

## 10.2 체크포인트에 필요한 것

전압 배열만 저장해서는 이어서 계산할 수 없습니다.

```text
신경 전압·시냅스 상태
불응기
발화율 필터
지연 큐와 현재 슬롯
입력 인코더의 시간 상태
난수 상태
활성 개입과 예약 명령
출력 디코더 상태
보조 제어 상태

MuJoCo 적분 상태
CPG·반사 상태
환경·외력
정확한 clock

데이터·모델·매핑·몸·환경 해시
```

복원은 모든 검사를 통과한 뒤에만 기존 인스턴스를 교체합니다. B fix_2에서 보완한 **실패 시 기존 상태를 보존하는 원칙**을 C에서도 유지합니다. 

B의 활성도 0~1을 C의 막전위로 임의 변환해서 이어 시작하지 않습니다. B에서 가져올 수 있는 것은 우선 **실험 조건·환경·시드**이며, C 신경계는 새로 초기화합니다.

## 10.3 “억제”의 의미를 나누기

C에서는 하나의 억제 버튼에 여러 의미를 섞지 않는 것이 좋습니다.

| 개입 | 의미 |
|---|---|
| `suppress_spiking` | 새로운 발화 발생 중지 |
| `mute_outgoing` | 해당 뉴런의 이후 출력 전달 중지 |
| `mute_edges` | 특정 연결 집합의 효력 변경 |
| `sensor_off` | 감각 입력 경계 차단 |
| `motor_disconnect` | 신경–몸 구동 연결 차단 |
| `assist_off` | 회피·후진 보조만 차단 |

뉴런의 발화를 막았다고 이미 이동 중인 스파이크나 발화율 필터, 몸의 관성까지 즉시 없어지는 것은 아닙니다.

**기존 지연 큐를 유지하는지, 제거하는지까지 개입 의미에 포함**해야 대조 실험을 해석할 수 있습니다.

# 11. 검증 기준

C의 검증은 “초파리가 움직였다”로 끝내면 안 됩니다.

## 단계별 필수 검사

| 단계 | 통과 조건 |
|---|---|
| **B 기준선** | 기존 B 호환 모드와 fix_2 검사 유지 |
| **데이터** | ID·방향·집계·좌우·제외 목록·해시 확인 |
| **단일 뉴런** | 적분·발화·리셋·불응기·지연 확인 |
| **작은 회로** | E/I, 순환, 고립 뉴런, 지연 큐, 개입 반례 |
| **CPU/GPU** | 동일 모델의 상태·발화 비교 |
| **입출력 포트** | 실제 ID, 자극 방향, 단위, 정답 정보 누출 검사 |
| **물리** | B 몸의 초기 정착·관절·접촉·보행·복원 |
| **폐루프** | C 출력이 실제 몸 행동에 기여 |
| **기록** | 구독·표시·저장 여부가 동역학을 바꾸지 않음 |
| **다조건 실험** | 여러 시드·마찰·장애물·감각·신경 개입 |
| **자원** | 실제 전체 데이터에서 메모리·속도·기록량 측정 |

## 반드시 들어가야 하는 대조 실험

특히 다음 비교가 중요합니다.

**화면 구독을 끈 경우와 켠 경우:** 신경 결과가 같아야 합니다.

**C_SHADOW와 C_STRICT:** 화면에 뇌가 보이는 것과 실제 몸을 제어하는 것을 구분합니다.

**모든 신경 출력 차단:** 남아 있는 운동 명령이 보조 제어에서 나오는지 확인합니다.

**C_ASSISTED와 C_STRICT:** 회피·후진 보조가 성능을 얼마나 바꾸는지 확인합니다.

**감각 채널 제거:** 해당 감각이 신경 출력과 행동에 영향을 주는지 확인합니다.

**원래 연결과 통제된 재배선:** 연결 구조가 과제 수행에 어떤 차이를 만드는지 확인합니다. 원래 연결이 항상 더 좋을 것이라고 미리 단정하지 않습니다.

## fix_2의 고착 검사는 유지

현재 개선된 기준은 그대로 가져갑니다.

이동이 요구되고 운동 연결이 켜진 구간에서 **3초간 수평 위치 범위 대각선이 1mm 미만이면 고착**으로 판단합니다. 표본 공백은 불완전한 기록으로 처리하고, 회피 종료 후 실제 전진 재개도 확인합니다. 알려진 실패 궤적을 새 코드에서도 실패로 검출해야 합니다.  

C가 나중에 정지·그루밍 같은 행동을 지원하면 과제에서 `motion_expected`를 명시적으로 바꿀 수 있습니다. 그러나 **뇌가 0을 출력했다는 이유만으로 이동 기대를 자동 해제하면 고장 난 모델이 검사를 피하게 됩니다.**

# 12. 로컬 구현 순서

이번에는 한 번에 C 전체를 만들기보다, 아래 순서로 작은 변경 단위를 만드는 것이 좋습니다.

| 순서 | 작업 | 해당 단계의 완료 기준 |
|---|---|---|
| **1** | B fix_2·원자료·환경 동결 | 기준 해시와 로컬 회귀 결과 확보 |
| **2** | B를 호환 어댑터로 감싸기 | 기존 행동·기록이 달라지지 않음 |
| **3** | 전뇌 데이터 로더 | 실제 자료의 manifest·CSR·통계 생성 |
| **4** | CPU LIF 기준 구현 | 작은 회로·지연·개입·복원 통과 |
| **5** | GPU 계산기 | CPU와의 비교 및 전체 자료 자원 측정 |
| **6** | 실제 감각·하행 출력 매핑 | ID·단위·좌우·자극 방향 검증 |
| **7** | 물리 몸과 시간 동기화 | 짧은 실제 C 폐루프 실행 |
| **8** | 대규모 UI·기록 | 선택 구독·바이너리 전송·청크 저장 |
| **9** | 대조군·개입군 실험 | 실패를 포함한 재현 가능한 결과 |
| **10** | C 릴리스 판정 | 계산·보행·생물학·성능 상태를 별도 공개 |

**첫 번째 코드 변경은 전뇌 파일을 읽는 것이 아니라, B의 `Engine`이 특정 `brain.a` 배열과 그룹 이름에 직접 의존하지 않도록 만드는 작업이어야 합니다.**

그다음 실제 전뇌 로더와 CPU 기준 모델을 독립적으로 붙입니다. 이렇게 해야 데이터 오류, 수치 계산 오류, 감각 매핑 오류, 몸 제어 오류가 한꺼번에 섞이지 않습니다.

## 최종 권장안

첫 C는 다음 조합으로 고정하는 것을 권합니다.

> **FAFB v783 전뇌 + 명시적인 LIF 모델 + 실제 ID 기반 감각·하행 출력 연결 + B의 물리 보행 유지 + 보조 제어를 분리한 실험 모드 + 선택 신호 모니터링·기록**
