## Recommended change

Reduce repeated fixed-authority interpretation within one actual validation operation. Add an explicit bounded `FixedAuthorityScope`, active only around production metadata preparation/admission/publication in the current tool/helper. Memoize only successfully validated parsed dictionaries returned by the literal registration/redistribution/v2/historical/current authority readers. Return deep copies. Do not cache raw bytes, live or frozen ledger values, requests, Q, worker results, process identity, pending/reservations/cost arithmetic, clocks, numerical arrays or installed/layout/oracle observations. Existing actual-first same-process AST cache and fresh source/layout/oracle/installed checks remain.

Each scope starts empty after the real ENTRY, is keyed by canonical root, reader identity and exact literal descriptor, is process-local and synchronous, and clears in `finally`. No persisted/preseeded cache, cross-process inheritance, free preparatory read, environment bypass or generic arbitrary-file cache. Keep the normal typed bounded .py/.ps1/.json reader and CPU guard unchanged. The common library remains untouched; .ps1 strict UTF8/path/no-reparse/SHA/byte and original NPZ/NPY pre-IO rejection remain.

Track all immutable text dependencies actually consumed while a fixed reader validates, including direct literal reads and transitive source/evidence descriptors. Do not retain their raw bytes or full ledger dictionaries. Before any commit, pre-spawn receipt/Popen boundary, first numerical/native import/array boundary, Q/contract/receipt/full-exit/helper-completion publication, revalidate those dependencies with fresh contained paths, bounded bytes/SHA/UTF8 as applicable and a current clock callback. Always retain independent fresh own/project/layout/installed/oracle checks. Never substitute a saved parent AST for actual child discovery. A scope hit still checks the actual clock. Cache only after successful complete validation, never an exception/partial result; root/descriptor mismatch is a miss or rejection, never a reuse.

Publish only after fresh revalidation. Integrate existing post-close readback/revocation/error paths: a late/drifting dependency must preserve first error, make the result unqualified and retain actual costs/ownership. Do not let `finally` replace the original exception or bless an already published stale result. When the tool leaves admission for external execution, clear the scope and preserve owned-identity closure. Dynamic admission facts are reread/recomputed even on a fixed-authority hit. If this design does not fit a particular boundary, leave it uncached rather than weaken freshness.

The expected benefit is fewer repeated JSON interpretation and dependency traversals within the same operation. No timing success is promised. The existing fixture30/24/20/16, suite120/110/100/90, helper/scanner/Ruff caps and shared600/local489 remain unchanged; actual fresh full-return timing determines success.
