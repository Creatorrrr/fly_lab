# E173 이후: 시작 응답과 근육별 출력 보호의 영향을 분리한다

목표는 동일한 전체 BANC 후보의 실제 자연 보행 F1–F8이다. E173 전체 비교의 invalid_not_tested와 history 미인증 상태를 유지한다. 완료된 static 부분의 양수 witness는 저장 command 근사에 필요한 정보가 양수 좌표에서도 전달될 수 있음을 보여준다. 다만 큰 startup 오차와 근육 예산 위반이 동시에 있어 어느 보호 조건이 개선을 막는지는 아직 분리되지 않았다.

다음 부모 설계는 static 가족에 한정한다. 같은 양수 계수 [0,2], 같은 QR·표본·목표를 사용하여 startup 보호와 MN/근육 보호를 각각 복원하는 최대 두 개의 고정된 대조를 검토한다. 두 보호를 함께 적용한 E169의 저장 affine 배제 증거와 비교한다. history의 실패를 다시 풀기 위한 설정 탐색은 하지 않는다. 어떤 보호의 일부만 시험한다면 그 범위를 명시하고, 전체 보호에 대한 결론으로 확대하지 않는다.

한 보호 집합만 추가해도 20% 개선이 유한 정밀도 상한으로 배제된다면 그 집합이 현재 고정 신호에서 충분한 제한 원인이라는 근거가 된다. 두 집합을 각각 적용했을 때 witness가 남아도 두 집합의 동시 충족, 다른 velocity·다리별·startup 최대값 조건의 충족은 자동으로 따라오지 않는다. 기각 또는 미결 결과에서 수치만 바꾼 재시도를 하지 않는다.

이 비교의 목적은 다음 실제 모델 변경을 선택하는 것이다. 시작 응답이 제한한다면 기존 신경/근육 상태가 초기 반응과 지속 반응을 구별하는 전달 동역학을 설계한다. 근육 보호가 제한한다면 같은 해부학적 MN의 모집·활성 구성과 pooling을 검토한다. 이 단계에서 보호 예산이나 startup 한도를 낮춰 통과시키지 않는다. 새 전달 가정은 공학적 가설로 기록하고, 긍정적인 저장 결과 후에도 전체 신경·신체 폐루프에서 검증해야 한다.

현재는 후속 방향과 읽기 전용 소스 검토 단계다. E174의 정확한 변수/행/허용치/입력 hash/실행 한도/판정 규칙은 별도 사전 설계로 동결한 뒤 구현한다. 실제 `gpt-6-sol`이 첫 구현과 첫 수정을 담당하고 부모가 설계·두 리뷰·잔여 수정을 담당한다. 새 원본 실행 및 fit은 아직 0이다. 기존 M2, 활성 UI, 미사용 F6 초기상태와 원래 F1–F8을 보존한다.
