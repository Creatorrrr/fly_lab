# E112b: 입력 재검산 오류의 기술적 복구

E112 첫 실행은 단일 스레드 BLAS의 합산 순서에 따른 반올림 차이 때문에 고정 background의 재계산 비트 일치 검사에서 중단됐다. 최적화, 전체 조건부 응답, 실제 신경/신체 전진은 모두 0회다. 외부 실행 시간은 4.179270400025416초이며 원본 9개 파일과 비용은 `e112-dense-foot-recruitment/parent-failed-preflight-review.json`에 보존했다. 원래 실패를 성공으로 바꾸지 않는다.

사용자가 정한 부모 설계→Sol 구현→부모 리뷰→동일 Sol 첫 수정→부모 재리뷰 순서가 이미 끝났으므로, 이번 남은 수정은 부모가 수행한다. Sol은 최종 부모 검토 후 아래 한 번의 실행만 담당한다. 기존 Sol xhigh를 사용하며 새 모델이나 최적화 가설을 설계하지 않는다.

## 바꾸는 검사

원래 E112 설계와 입력 NPZ SHA256 `47ab37cb492afa2b6d5ca20dc5fbf0a8429167cea401c20c43aa17f7e89f999c`는 유지한다. 저장된 background 배열은 원래 부모 baseline과 바이트 단위로 같아야 하며, 실제 계산에는 그 저장 배열을 그대로 쓴다. 세 target-only 정규화 값도 종전 비트 일치를 유지한다.

오직 `current - source_rate @ current_w.T`의 재계산 검사를 float64 합산 오차 경계로 바꾼다. 49항 내적과 최종 뺄셈에 대해 k=50, eps=2^-52(단위 반올림 오차의 두 배), gamma=k*eps/(1-k*eps)를 사용한다. 각 원소의 상한은 `nextafter(2*gamma/(1-gamma)*(abs(current)+abs(source_rate)@abs(current_w).T), +inf)`이다. 두 가지 합산 순서의 오차와 절댓값 합 계산의 오차를 포함하는 보수 경계이며, 임의의 맞춤 허용치가 아니다. 유한 float64 및 정상 범위의 입력·곱만 허용한다. 재계산·원본·절댓값 차이·절댓값 합·경계를 먼저 NPZ에 보존하고 판정한다. 원자료나 생물학적 합격 기준은 수정하지 않는다.

근거는 [Higham, Accuracy and Stability of Algorithms in Numerical Linear Algebra, Chapter 2](https://nhigham.com/wp-content/uploads/2023/10/high99n.pdf#page=4)의 부동소수점 모델과 gamma 경계다. 이 자료의 수치해석 원리를 현재 내적 및 뺄셈에 적용한 것은 본 구현의 분석이다. 실제 원본 입력, 한 ULP 차이, 유의미한 변조의 거절, 정확한 파일 해시 유지와 오류 시 원자료 보존을 CPU 테스트로 확인한다. CUDA/신경 응답/실제 신체는 테스트에서 실행하지 않는다.

## 남은 자원과 실행 경계

원래 공유 상한506초를 유지한다. 기존321초에 실패4.179270400025416초를 합친325.1792704000254초를 **326초**로 올림 계상하여 새 프로세스 한도를 **180초**로 줄인다. fit150초, 각 다리24초·1000개 vector, 합6000개 vector, 각 다리 SLSQP 한 번, 원래 초기점/가중치 범위/38tau/원래99 및 내부 여유/shape 판정은 그대로다. 자동 재시도나 최적화 재시작은 없다. OMP/MKL/OPENBLAS threads1 환경과 실제 Torch/CUDA 장치를 기록한다.

새 출력은 `e112-dense-foot-recruitment-v2/`이며 기존 실패 디렉터리를 덮어쓰지 않는다. 외부 감독 프로세스는 준비·정리까지180초 이내인지 기록한다. 저장·오류·부모 리뷰까지 기존 E112 회계 규칙을 따른다. 실제 신경/물리 시간0, F6 새 자세 노출0이다. 최종 부모 소스 검토 후에만 한 번 실행하며, 조건부 결과는 전체 BANC 폐루프 보행 또는 F1–F8 성공으로 해석하지 않는다.
