### ① 오류가 발생하면 ‘새 실험’으로 복구할 수 없습니다

**위치:** `flylab/c/server.py:78–93`, `flylab/c/engine.py:361–362`

현재 `init`은 기존 엔진이 있으면 먼저 체크포인트를 저장하고, 그 뒤 새 엔진을 만듭니다. 그런데 `checkpoint()`는 신경 또는 몸이 오류 상태이면 저장을 거절합니다. 따라서 **오류가 발생한 상태에서는 새 실험을 만들기 전에 다시 예외가 발생**합니다.  

다음 순서로 재현했습니다.

```text
정상 실험 생성
    ↓
동일 뉴런에 각각 허용되는 100mV 자극 11개 예약
    ↓
합산 입력이 backend 허용 범위를 초과
    ↓
Finite mV input per included neuron required
    ↓
새 실험 요청
    ↓
Faulted state is not a restorable checkpoint
```

정상 상태에서는 같은 새 실험 요청이 성공했습니다. 즉, 일반적인 초기화 실패가 아니라 **오류 이후 복구 경로의 문제**입니다.

이 반례는 명시적인 테스트용 몸과 작은 회로를 사용했습니다. 실제 MuJoCo에서 같은 자극으로 넘어짐이 발생했다는 뜻은 아닙니다. 다만 문제의 원인은 공통 서버·체크포인트 흐름에 있습니다.

**권장 수정:** 정상 상태라면 기존처럼 체크포인트를 저장하되, 오류 상태라면 복원 가능한 체크포인트 대신 진단 기록을 남기고 명시적인 새 실험을 허용해야 합니다. 새 인스턴스 생성 자체가 실패하면 기존 인스턴스를 유지하는 원자적 교체 원칙도 지키는 것이 좋습니다.

같은 시점에 중첩되는 자극의 **합산 입력 검증**도 추가할 만하지만, 그것만 고쳐서는 다른 원인으로 발생한 오류 이후 초기화 문제까지 해결되지는 않습니다.

### ② ‘전뇌 계산 통과’ 판정이 작은 회로에서도 나옵니다

현재 코드는 읽어들인 그래프를 500스텝 계산한 뒤, 전체 스냅샷인지 검사하지 않고 `full_brain_compute`를 통과시킵니다. 이미 `GraphStore.full_brain` 판정이 있지만 이 검증 경로에서 사용하지 않습니다.

**계산이 정상 수행됐다는 판정은 맞지만, ‘전뇌 계산’이라는 검사 이름과 통과 조건이 맞지 않습니다.**

권장 수정은 검사를 분리하는 것입니다.

```text

```

두 번째 검사는 원본 뉴런 목록, 제외 정책, 데이터 스냅샷, 원자료 해시와 실제 계산 노드 수를 함께 확인해야 합니다. 단순히 특정 뉴런 수를 하드코딩하는 방식은 피하는 것이 좋습니다.

**이번 실제 데이터 검증에서는 전체 자료를 별도로 확인했습니다.** 따라서 이 결함이 아래의 139,255개 뉴런 실행을 부정하는 것은 아닙니다. 검증기가 다른 입력을 잘못 승인할 수 있다는 문제입니다.

### ③ 새 환경에서 문서대로 binding을 재생성하면 실패합니다

**위치:** `docs/C_ARCHITECTURE.md:32–39`, `tools/build_c_bindings.py:65–71`

문서는 다음 경로로 binding을 만들도록 안내합니다.

```bash
python tools/build_c_bindings.py \
  --graph data/fafb783/bundle \
  --out data/fafb783/bindings.json
```

하지만 `data/fafb783/bindings.json`은 이미 저장소에 포함되어 있고, 빌더는 기존 파일 덮어쓰기를 거절합니다. 따라서 문서의 명령을 그대로 실행하면 종료 코드 1과 함께 다음 오류가 나옵니다.  

```text
Binding profiles are versioned; choose a new output path
```

**불변 파일 정책 자체는 좋습니다.** 문제는 그 정책과 새 환경의 실행 안내가 맞지 않는다는 것입니다.

실제로 공식 자료를 새로 내려받아 전뇌 bundle을 만든 뒤에는, 저장소의 기존 binding이 가리키는 graph hash와 새 graph hash도 달랐습니다. 이때 거절하는 것은 올바른 무결성 검사이므로, 검사를 제거하지 않았습니다.

대신 새 경로에 binding을 재생성했고, **기존 기본 binding과 달라진 최상위 필드는 `graph_hash` 하나뿐**이었습니다. 감각·운동 대상 뉴런과 gain을 임의로 조정하지 않은 상태로 실제 물리 검증을 진행했습니다.

문서에는 다음처럼 새 버전 경로를 사용하는 절차를 넣는 것이 좋습니다.

```bash
python tools/build_c_graph.py --download --unknown-policy mask_zero \
  --raw data/c_new/raw --out data/c_new/bundle

python tools/build_c_bindings.py \
  --graph data/c_new/bundle \
  --out data/c_new/bindings.json

python run_c.py \
  --graph data/c_new/bundle \
  --bindings data/c_new/bindings.json
```

`c_new`는 아직 존재하지 않는 경로여야 합니다. 원래 bundle의 manifest가 커밋에 없으므로, **기존 graph hash와 달라진 정확한 원인까지는 단정하지 않았습니다.**

## 3. C 설계에서 잘 구현한 부분

**단순히 뉴런 이름과 그래프만 늘린 구현은 아닙니다.** 다음 경계가 실제 코드와 실행 결과에 반영되어 있습니다.

| 설계 항목 | 평가 |
|---|---|
| **실제 전체 데이터 로더** | 원본 뉴런 목록·해시·집계 연결을 유지하고 전체 bundle을 만들 수 있음 |
| **독립적인 신경 계산** | 실제 전체 뉴런 상태와 희소 연결을 계산 |
| **시간 동기화** | 현재 시점의 신경 출력으로 다음 몸 구간을 진행하며 미래 출력을 과거 몸에 적용하지 않음 |
| **모드 분리** | B_COMPAT·C_SHADOW·C_ASSISTED·C_STRICT의 역할을 구분 |
| **명령 출처 기록** | 신경·보조·B 명령을 구분하고 최종 적용 명령을 기록 |
| **복원 상태 구성** | 전압뿐 아니라 시냅스 상태·불응기·지연 큐·몸·제어 상태를 저장 |
| **단위와 승인 범위** | 전압·발화율·원시 스파이크와 기술·과제·생물학 검증을 구분 |

특히 **C_STRICT에서 신경 출력이 0이라고 B가 조용히 대신 움직이지 않는 점**, C_ASSISTED와 C_SHADOW의 명령 출처를 명시하는 점은 중요합니다. 이 구분은 원래 설계의 핵심이었고, 이번 실제 실행 기록에서도 확인했습니다. 

다만 GPU 코드가 존재한다는 것과 GPU 계산이 이번 환경에서 검증됐다는 것은 다릅니다. **MPS·CUDA 정확도와 성능에는 이번 CPU 결과를 대신 적용하지 않겠습니다.**

## 4. 자연 탐색 능력은 아직 별도 검증이 필요합니다
