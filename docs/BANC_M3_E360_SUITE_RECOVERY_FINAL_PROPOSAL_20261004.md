## 리뷰를 마친 수정안

ROOT 설계 → 실제 GPT-6 Astra/max 리뷰 → ROOT 반영 → 실제 GPT-6.1 Sol/high 구현 → ROOT 1차 리뷰 → 같은 Sol의 한 번의 수정 → ROOT 재리뷰 → ROOT 잔여 수정 순서로 진행했다. Sol의 두 번째 수정은 요청하지 않았다. 중간 사본은 불변 기록으로 유지하고 최종 사본을 분리했다.

- 오래된 테스트의 시간 초과 예외 기대를 실제 선행 오류에 맞췄다. 일반적인 생성 전 실패와 알 수 없는 프로세스 소유권 검증은 유지했다.
- `closed_exit`와 `closure_sources` 한 번의 호출 안에서만 검증된 고정 설정 해석을 재사용한다. 반환 결과·실시간 원장·현재 소스·원본 데이터·시계는 재사용하지 않는다. 실제 시작 시각, 파일 재검증, 실패 후 재사용 금지와 로컬 정리 경계를 유지한다.
- 스크립트의 `__main__`과 테스트가 가져오는 모듈이 같은 인증된 실행 상태를 보도록 실행 중에만 연결한다. 현재 소스·경로·모듈 충돌을 확인하고 종료 시 이전 모듈과 패키지 상태를 복구한다.
- 테스트별 setup/call/teardown 시작과 실제 보고를 별도 진단 파일로 저장한다. 실제 부모 시작 시각과 시계를 사용하며, 기록 저장 실패나 부분 기록으로 전체 테스트 성공을 인정하지 않는다. 기록 하나의 파일 재검증은 저장 전과 실제 fsync·닫기·재읽기 후의 두 번을 유지한다.
- 테스트 실패 뒤 러너·시간 제한·저장이 실패해도 첫 테스트 실패와 후속 오류를 보존한다. 정상적인 실패 코드 반환도 같은 방식으로 보존한다. 불합격 receipt의 종료 코드와 실제 러너 반환을 일치시킨다.
