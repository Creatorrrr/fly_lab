1. **Pugliese 계열의 rate 동역학, 적응 상태, 희소 CUDA 계산, 감각·운동 인터페이스가 이미 있습니다.** 이전 답변의 “rate 모델을 첫 대안으로 도입하자”는 제안은 현재 구현에 맞지 않습니다.

# 1. 첨부에서 확인한 실제 병목

## 1-1. 제품 경로와 최근 M3 연구 경로를 구분해야 합니다

**[코드 확인]** 제품의 기본 연결은 다음과 같습니다.

```text
BancWalkingSession.advance()
    → RateBodyAdapter.encode()
    → 신경 입력 + 하행/목표 관련 구동
    → AdaptiveRateNetwork.advance_readout()
    → RateBodyAdapter.decode()
    → FlyGymBody.step_joint_targets()
    → 실제 신체 관측을 다음 제어 주기에 사용
```

`research_rate.py`는 이미 Pugliese 구현의 참조 커밋을 명시하고, `adaptive_rate.py`에는 발화율과 적응 상태를 함께 적분하는 구현이 있습니다. 신경 상태도 제어 주기 사이에 유지됩니다. 따라서 **“기존 코드가 매 프레임 신경 상태를 0으로 초기화할 수 있다”는 일반적인 우려를 현재 코드의 결함으로 취급할 근거는 없습니다.**

또한 `FlyGymBody.step_joint_targets()`는 사전 정의된 CPG를 진행시키지 않는 직접 입력 경로입니다. 클래스 내부에 `HybridTurningController`와 CPG 객체가 존재한다는 사실만으로 외부 CPG 보행이라고 판단해서도 안 됩니다.

*첨부 근거: K2 — `banc_walking.py:377–439`, `adaptive_rate.py:212–255`, `research_rate.py:146–185`, `body.py:425–493`.*

반면 **최근 후보의 경로는 위 기본 설정만으로 설명할 수 없습니다.**

```text
reference_parameter_direction.collect()
    → pin된 coordination_parameter_direction.assemble()
    → GroupedCurrent + SSPAdjointModel + MonotoneDecoder
    → CheckpointedControlRollout
    → 실제 float32 후보 효능 생성
    → candidate_body_handoff
    → SSPEfficacyTrial(SSPRecoveryResourceTrial.from_checkpoint(...))
    → 실제 신체 실행
```

여기에 필요한 SSP·decoder·rollout 핵심 구현 중 여러 파일은 ZIP에 없습니다. **M2 설정의 시간상수나 기본 decoder를 최근 M3 후보의 실제 설정이라고 단정할 수 없습니다.**

*첨부 근거: K3·K4 — `coordination_parameter_direction.py:1169–1259`, `common_descent_body.py:230–255, 1442–1482`.*

## 1-2. 가장 중요한 불일치: 학습은 보행 중간의 20ms, 적용은 시작부터

**[코드 확인]** `reference_parameter_direction.py`의 학습 창은 제어 인덱스 `100, 164, 228, 292`에서 시작합니다. 각 창은 4개 제어 구간, 즉 **20ms**입니다.

각 창에서는 저장된 `rate`, `adaptation`, `bank`, `original_activation`을 복원하고 **저장된 감각 구동**으로 신경·decoder를 진행합니다. 손실의 `q`는 실제 몸의 관절 측정치가 아니라 **decoder가 낸 관절 명령**입니다.

현재 방향 선택은 다음과 같습니다.

\[
\theta_{\mathrm{actual}}
=
\operatorname{float32}
\left(
1-0.001\frac{g_R}{\max |g_R|}
\right)
\]

이 식에는 startup 제한이 들어 있지 않습니다. 반면 실제 신체에서는 이 효능을 처음부터 적용하고, 99번째 제어 시점인 **0.495초**에 startup을 판정합니다.

*첨부 근거: K3 — `reference_parameter_direction.py:327–341, 786–800, 860`; K4 — `candidate_body_handoff.py:1251–1279`.*

**[첨부 기록]** E353 교사의 고정 cadence는 약 2.383Hz로, 한 주기는 약 **420ms**입니다. 따라서 20ms 학습 창은 그 주기의 약 **4.8%**입니다.

**[추론]** 이 학습은 “특정 저장 상태 주변에서 명령을 조금 개선할 수 있는가?”에는 답하지만, 다음을 직접 학습하지는 못합니다.

- 시작 상태에서 보행 상태에 도달하는 과정.
- 한 주기를 넘어 신경·운동 상태가 반복적으로 유지되는 과정.
- 후보가 바꾼 신체 상태가 감각을 바꾸고, 그 감각이 다시 후보를 바꾸는 효과.

**저장 입력 손실의 개선이 실제 보행 개선으로 이어지지 않아도 이상하지 않은 구조입니다.** 다만 이것이 실제 실패의 유일한 원인이라는 것은 아직 추론입니다.

## 1-3. ‘완전 주기 0’의 의미도 더 정확해졌습니다

**[코드 확인]** 기존 평가기는 접촉 전환을 곧바로 보행 주기로 세지 않습니다.

`phase_and_events()`는 **0.3초보다 짧은 전진 bout를 제외**하고, 발의 앞뒤 위치에서 **AEP→PEP→AEP**에 해당하는 완전 주기를 찾습니다. 접촉 전환 횟수는 별도의 기술적 통계입니다.

따라서 E335의 최장 전진 bout가 **0.21초**라면, 그 실행에서 적격 주기가 모두 0인 것은 평가 정의와 일치합니다. 이것만으로 **“다리가 전혀 반복 운동을 하지 않았다” 또는 “신경 회로에 리듬이 없었다”**고 결론낼 수는 없습니다.

*첨부 근거: K5 — `analyze_c_banc_biological_gait.py:180–240, 369–375`.*

**이전 답변에서 제안한 접촉 기반 주기 정의나 새로운 1.5초 통과 수치는 적용하지 않는 것이 맞습니다.** 기존 정의와 F1–F8을 유지하고, 적격 전진이 끊기는 원인과 그 안에서의 다리 협응을 분리해 분석해야 합니다.

## 1순위 — startup을 보존하는 제약식 안에서 효능을 학습

**선정 이유:** 최근 후보가 실제 보행 평가 영역에 도달하기 전에 탈락할 가능성을 직접 다룹니다.

현재 startup 제한은 다음 네 개입니다.

\[
q_{\mathrm{RMS}}\le0.018,\quad
q_{\max}\le0.04,\quad
t_{\mathrm{RMS}}\le0.009,\quad
t_{\max}\le0.025
\]

여기서 \(q\)는 **관절 명령 오차**이며, 실제 기하학적 무릎 운동폭과 다릅니다.

**[첨부 기록]** E359 producer의 `qmax≈0.039636`은 제한까지 약 **0.000364rad**밖에 남지 않았습니다. 이 기록이 독립 감사된 기준선은 아니지만, 시작 구간에 여유가 적다는 가설을 세울 충분한 이유입니다.

**[제안·미실행]** 현재의 고정 정규화 방향을 무조건 적용하는 대신, **startup을 악화시키지 않는 방향 중 교사 명령 손실을 줄이는 방향**을 선택합니다. 신경 모델·선택 edge·decoder·신체는 그대로 둡니다.

현재 `common_direction()`도 확인했지만, 이것은 C와 S proxy의 공동 방향을 구하는 것이며 **99-control startup 제약을 포함한 최적화는 아닙니다.**

*첨부 근거: K3 — `make_direction():327–341`, `common_direction():246–305`; K4 — `startup99():343–369`; K7 — E358/E359 결과.*

## 2순위 — 20ms 저장 입력 적합을 넘어 ‘다중 주기·후보가 방문한 상태’로 학습 범위 확장

**선정 이유:** startup 통과만으로는 지속 전진·협응·반복성이 생기지 않습니다.

**[추론]** 네 개의 짧은 창을 저장 상태에서 각각 다시 시작하면, 각 창의 명령은 개선돼도 **창 사이 상태 이동과 한 주기 이상의 유지**는 개선되지 않을 수 있습니다.

**[제안·미실행]** 1순위 이후에는 별도 변경으로 다음을 적용하는 것이 유망합니다.

- 신경 상태를 재설정하지 않는 연속 구간으로 학습 길이를 늘린다.
- 후보가 실제 몸에서 만든 감각·상태를 다음 학습 데이터에 포함한다.
- 명령 모방 손실뿐 아니라 기존 평가기의 bout·주기·협응·slip 결과로 후보를 선택한다.
- 참조 위상이나 궤적 정렬은 학습 측에서만 사용하고 최종 정책 입력에서는 제외한다.

이 방향은 **학습 데이터와 정책이 실제 방문하는 상태의 차이**를 다루는 DAgger 계열 방법과 연결됩니다. 다만 현재 E353처럼 정해진 cadence 궤적을 재생하는 교사를 그대로 “DAgger 전문가”라고 부르면 안 됩니다. 임의의 학생 상태에서 적절한 행동을 반환하는 교사 인터페이스가 별도로 필요합니다. 원 논문과 공개 구현은 이 구분을 확인하는 데 유용합니다. :chatgpt-content-reference{index="23"}

구현상으로도 단순히 `steps=4`를 크게 바꾸는 작업이 아닙니다. 현재 `max_controls=4`, 16×42 정규화, 저장 창·감사 계약이 고정되어 있으므로 **연속 구간 확장은 별도의 명시적 실험 버전**이어야 합니다.

- 선언된 노드 **158,706개**, pair edge **11,584,852개**.
- 교정 대상 edge **725,849개**, 파라미터 그룹 **8,547개**.
- 양의 그룹별 θ로 선택 edge의 float32 효능을 변경.
- 나머지 edge 및 원래 해부학적 구조 보존.
- 실제 배포 가중치 palette가 **16,384개 이하**여야 하는 계산상 제약.

*첨부 근거: K3 — `coordination_parameter_direction.py:88–110, 1331–1357`.*

따라서 새 학습법도 다음과 같이 현재 구조를 활용해야 합니다.

\[
W_e^{\mathrm{candidate}}
=
\operatorname{float32}\!\left(
W_e^{\mathrm{base}}\theta_{g(e)}
\right)
\]

원래 시냅스 수·노드·연결은 그대로 두고 **효능 overlay만 변경**하는 방식입니다. 16,384 palette 제한은 생물학적 가정이 아니라 계산 backend의 제약이므로, 무제한 per-edge 학습을 도입하면 실제 실행 경로까지 바뀔 수 있습니다.

다만 코드의 **선언된 roster 전체 보존**과 **BANC 원 데이터 전체의 완전성 검증**은 구분되어 있습니다. 원본 배열이 없으므로 이번 조사에서 후자를 확인한 것은 아닙니다.

# C. 가장 유망한 접근의 첫 실험

## 실험: startup 제약을 포함한 신경 효능 방향 선택

**[제안·미실행]**

### 가설

> 기존과 같은 BANC·신경 동역학·decoder·신체에서, startup을 보존하도록 효능 업데이트 방향을 제한하면, 저장 입력 손실 개선을 유지하면서 실제 1.5초 평가까지 도달할 수 있다.

이 실험의 첫 목적은 **자연 보행 완성**이 아니라, **현재 개선 방향이 시작 구간을 깨뜨리는 문제를 해소하고 보행 가설을 실제로 평가할 수 있게 만드는 것**입니다.

### 한 가지 주요 변경

**`make_direction()`의 방향 선정 규칙만 startup 제약을 고려하도록 바꿉니다.**

신경 모델, 8,547개 그룹, 선택 edge, decoder, 신체, 교사 목표, 네 학습 창, 평가기와 F1–F8은 고정합니다.

예를 들면 다음의 국소 제약 문제를 사용할 수 있습니다.

\[
\delta^*
=
\arg\min_{\delta}
g_R^\top\delta+\frac{\lambda}{2}\|\delta\|^2
\]

\[
\text{subject to}\quad
\|\delta\|_\infty\le10^{-3},\qquad
\widehat c_{\mathrm{startup},k}(\delta)\le0
\]

\[
\theta_{\mathrm{actual}}
=
\operatorname{float32}(1+\delta^*)
\]

\(\widehat c\)는 기존 네 startup 제한의 국소 근사입니다. 특히 최대 오차에 가까운 **시간·관절 성분**의 변화부터 제한하면 전체 거대 Jacobian을 만들지 않고도 시작할 수 있습니다.

**여기에는 미검증 부분이 있습니다.** 현재 rounded-adjoint는 실제 물리 폐루프 전체의 정확한 Jacobian으로 검증된 것이 아닙니다. 따라서 이 제약식은 **후보 제안기**이고, 실제 startup 통과 여부는 기존 신체 실행으로 판정해야 합니다. float32 반올림 후의 θ와 palette 제한도 다시 확인해야 합니다.

제약을 만족하는 유의미한 개선 방향이 없으면 **“이번 파라미터 집합·국소 근사에서는 유효 방향 없음”**으로 기록합니다. startup threshold를 완화하거나 외부 warm-start를 넣어 통과시키지 않습니다.

### 비교군

| 군 | 정의 |
|---|---|
| **기준군** | 최근 연구가 사용하는 **θ=1의 동일 SSP 체크포인트**. M2가 아님 |
| **후보군** | 같은 체크포인트에 startup 제약으로 선정한 θ 하나를 적용 |
| **참고 기록** | E358의 기존 방향은 저장 입력·producer 결과의 비교 자료. 기술적 무효였으므로 유효 신체 대조군을 대신하지 못함 |

새 원본 실행은 기존 승인 범위와 별도로 계획해야 합니다. 현재 P10을 수행하면 이 비교까지 자동 승인되는 것은 아닙니다.

### 필요한 코드·데이터

기존의 `collect()`, `patch_weights()`, `body_data()`, `initial_body()`, `startup99()`, `screen()`, 독립 body audit를 재사용합니다.

추가로 필요한 것은 **99-control startup의 기준 명령·tendon 목표, 상태·감각 구동, 최근 후보의 실제 θ·선택 가중치, 누락된 adjoint/SSP/decoder 구현**입니다. 정확한 최대 오차의 시간·관절을 알아야 제약을 구성할 수 있습니다.

### 성공 기준: 기존 기준 그대로

|---|---:|

**2단계 — 같은 인스턴스를 이어서 실제 1.5초**

|---|---:|

관절·신경 상태를 0.5초에 다시 설정하거나 교사로 시작시켜서는 안 됩니다. **시작부터 적용한 같은 후보가 99-control 검사를 거쳐 300-control까지 연속 실행**되어야 합니다.

### 실패를 구분하는 방법

**기술적 무효:** 소스 등록·실행 시간·결과 보존·감사 실패. 보행 가설 판정 보류.

**startup 기각:** 출처와 raw가 유효한 실행에서 기존 네 제한 실패. 업데이트 방법에 대한 유효한 부정적 결과.

**보행 기각:** startup 및 실제 1.5초 실행은 유효하지만 bout·주기·slip 등이 기준 미달.

**단기 후보 적격:** 위 기준 통과. 다음 10초 평가로 승격할 자격이지 F1–F8 완료가 아님.

### 자원과 예상 소요

**[첨부 기록]** E358은 신경 후보 작업 약 23.3초, 별도 감사 약 2.4초, 신체 prefix 작업 약 48.3초였고 E359 prefix도 약 46.6초였습니다. 따라서 **“시뮬레이션 1.5초니까 현재 20초 원본 한도 안에 충분하다”는 추정은 성립하지 않습니다.**

**[계획 추정]** 누락 소스·데이터 확보와 실행 복구 이후, 제약 방향 선정 및 기존 경로 통합은 **약 2–4 인일**의 작업 묶음으로 볼 수 있습니다. 전체 계산 시간은 startup 민감도 계산 방식과 실제 backend 측정에 따라 정해야 합니다. 기존 시간 제한에 맞지 않으면 코드 경로 최적화 또는 별도 자원 제안이 필요하며, 이를 무료 준비·숨은 warm-up으로 처리해서는 안 됩니다.

현재 요구 환경은 PyTorch/CUDA 신경 실행과 CPU MuJoCo 물리를 함께 고려해야 합니다. 대규모 PPO나 A100급 학습 환경 도입은 첫 실험의 필수 조건이 아닙니다.

## 내부 리듬과 외부 위상의 경계

# 3. 실제 후보 평가 시간을 줄일 수 있는 부분

**가장 큰 재사용 자산은 외부 저장소가 아니라 이미 만들어진 현재 M3 경로입니다.**

| 재사용 대상 | 줄일 수 있는 작업 | 유지할 경계 |
| --- | --- | --- |
| collect()와 기존 rounded 후보 검사 | 새로운 학습 환경·입력 포맷 작성 | 저장 입력 개선과 물리 개선을 분리 |
| patch_weights() | graph 보존·선택 edge·float32 배포 처리 | 그룹·부호·palette 조건 유지 |
| body_data()·initial_body() | 같은 후보 전달 증명 | stale 후보나 다른 체크포인트로 대체하지 않음 |
| startup99()·screen()·gait evaluator | 새로운 판정 체계 작성 | 고정 threshold 유지, 이미 계산된 상세 결과만 보존 |
| 현재 신체·교사·접촉 수집 | Flybody 원 저장소로 다시 이주 | 같은 body asset·축·마찰·tendon·초기 조건 유지 |

**[코드 확인]** body.py:42–45는 tendon 및 whole-body 경로를 **CPU 물리로 제한**합니다. 따라서 body_warp.py가 존재한다거나 FlyGym이 GPU backend를 제공한다는 이유만으로 현재 후보를 바로 GPU 물리로 전환할 수는 없습니다.

GPU 물리 이식은 접촉·tendon·정밀도·저장 상태 재현을 다시 확인해야 하는 **별도 공학 변경**입니다. 첫 후보를 판정하기 위해 동시에 수행할 작업은 아닙니다.

실행 준비의 중복 source 스캔·import·초기화 비용은 현재 시간 기록을 바탕으로 줄일 수 있지만, **검증을 생략하거나 실행 밖으로 비용을 숨기는 방식이 아니라, 같은 검증 범위 안에서 중복 계산을 줄이는 방식**이어야 합니다. 생성 자료 경로의 성능 개선도 원본 경로에 자동으로 전이된다고 가정하지 않습니다.

## E-2. 원본 배열과 실제 후보 자산

필요한 것은 현재 roster/CSR/원래 count·NT 주석, 725,849개 선택 edge 위치와 8,547개 그룹 대응, baseline 및 candidate θ, 배포 float32 가중치, 전체 checkpoint 상태와 resolved config입니다.

이 자산 없이는 다음을 확정할 수 없습니다.

- 어떤 세포·분절·길항 경로가 실제로 교정되고 있는지.
- 중추 연결의 유효 부호와 0 효능 경로의 분포.
- 최신 후보의 실제 시간상수·적응·decoder 설정.
- 선언된 roster 보존과 원 데이터 완전성의 관계.

## E-4. 신체·실행 환경

핀된 FlyGym checkout, 실제 XML/MJCF·mesh·tendon·접착 자산과 해시, 설치된 패키지 lock, 실행 당시 장치 정보, 기존 6개 목표 시나리오 정의가 필요합니다.

현재 requirements는 설치 의도를 보여줄 뿐 실제 설치 환경과 동일하다는 증거는 아닙니다. 또한 첨부에 GPU 샘플러 정보가 있다는 사실과 **물리까지 GPU에서 실행됐다는 주장**은 구분해야 합니다.

## 문헌 조사 자체의 한계

FlyGM은 본문·부록의 입력 정의까지 확인했지만 코드 접근은 실패했습니다. 일부 논문은 직접 페이지 접근 제한 때문에 검색에 제공된 원문 텍스트를 함께 사용했습니다. PDF 그림의 화면 검사는 실패했으므로 **그림에서 새 수치를 측정하거나 시연 영상으로 안정성을 인정하지 않았습니다.** Guan 등의 최신 사전논문은 전체 구현까지 확인하지 못했습니다.

따라서 이 답변은 **공개 논문·공식 코드의 정적 조사와 첨부 소스 비교**이며, 공개 프로젝트나 사용자 후보의 실행 재현 완료 보고가 아닙니다.

## 최종 권고

**첫 과학 실험은 “신경 모델 교체”가 아니라, 현재 make_direction()을 startup 제약을 만족하는 방향 선택으로 바꾸는 것입니다.** 기존 신경·decoder·신체를 유지한 채 시작 구간을 통과하고, 같은 후보를 실제 1.5초까지 평가하십시오.

그다음에는 **20ms 저장 입력 적합에서 다중 주기·후보 상태를 포함한 학습으로 넘어가는 것**, 그리고 **Sapkal 등의 새 회로·감각 결과로 고유감각·하중·길항 협응을 교정하는 것**이 우선입니다.

현재 가장 중요한 다음 증거는 더 작은 저장 손실이 아니라, **출처가 유효한 동일 후보가 startup을 보존하면서 실제 감각 폐루프에서 0.3초 이상의 전진 bout와 여섯 다리의 적격 주기를 만들고, 기존 slip 기준을 통과하는 기록**입니다.
