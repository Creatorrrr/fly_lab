# E231: E230 기록 분기의 기술 복구

E230은 첫 변경 control1620의 신체 적분 후 파일 스트림 `physical`을 tuple로 덮어써 중단됐다. 대조군2000와 변경군650 native steps는 보존됐고, 전체 변경 효과는 판정되지 않았다. 실패 원본·소스·회계는 동결한다. 이 단계는 새 보행 가설이나 파라미터 탐색이 아니라 **같은 Sol의 첫 결함 수정과 한 번의 명시적 기술 복구**다. E230 실패를 지우거나 자원을 초기화하지 않는다.

실제 gpt-6-sol/high가 `tools/probe_c_banc_m3_rf_tibia_hold_recovery.py`, `tests/test_c_banc_rf_tibia_hold_recovery.py`만 소유한다. E230 동결 구현을 별도 E231 경로/스키마/해시로 복사하고 이름 충돌을 수정한다. 실제 첫 qpos/qvel/ctrl 차이 분기 이후에도 JSONL 파일에 해당 행과 다음 행을 쓸 수 있음을 생성 fixture로 확인한다. 가능하면 해당 기록 분기를 작은 함수로 분리하여 같은 실행 코드를 검사한다. 관측·물리·명령·판정 알고리즘은 변경하지 않는다. 부모 SECOND 리뷰 뒤 잔여 결함은 부모가 마저 수정한다. Sol에게 원본 실행 권한은 없다.

E230 설계의 event25/control1607 시작, sham→rf_tibia_hold 각1608–1647/40controls/2000steps, joint26만1620–1635에1619명령 유지, 나머지41목표/8tendon/adhesion 및 세계/모델/seed는 그대로다. 완전 sham과 변경 전 lead는 E229/E228 원자료와 정확 대조한다. 실제 접촉 Jacobian·AP/접선 power·COM·root angular·다리별 힘·slip을 동일 저장한다. 초기방향 thorax 기준 후진25%감소/최저속도+.5mm/s/전진손실≤.02mm 및 RF 반력20%감소 기준을 유지한다. 완전하고 건강한 창만 판정하며 결과에 따라 E230에 이미 고정한 성공/실패 분기를 따른다. 추가 anchor/관절/기간 검색은 없다.

원본 신체 job1/retry0/CPU1/GPU0/body1/shadow1, 과학4000steps/.4초, 접촉최대32000/Jac64000, 신경/fit/solver0. 내부30초/마감5초예약/외부35/감독40초, RSS6GiB/출력128MiB/free2GiB는 그대로다. E230 실제2650steps와11.3775641초 비용을 모두 보존한다. 현재 누적6062.944038699661/6094초·잔여31.055961300338822초에서 **실행 전 단계 배정10초를 추가해6104초**, 새 잔여41.055961300338822초 중40초를 예약한다. 이는 실행 후 실패한 상한을 바꾸는 일이 아니며 E231도 실패하면 자동 재시도하지 않는다. 사용자 지정이 없는 전체 시간/토큰 상한은 만들지 않는다.

E230의 incomplete verdict, E225 startup 실패·10초 미완료·적격주기0, E228 두 hold 기각, E229 자기관절 전방미끄럼 설명 기각을 보존한다. E150/M2/UI/F6미노출/F1–F8과 전체 목표 미완료를 유지한다. 준비·생성·부모 검산·에이전트 읽기 비용은 원본 회계와 구분하고 미계측을0으로 주장하지 않는다.
