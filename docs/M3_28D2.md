# S28 ROOT 수정 설계 — 명시적인 읽기 전용 engine 저장소 검사

ROOT FIRST의 F3_PUBLIC_EXTENSION_INSPECTION_UNPROVEN을 해결하기 위한 설계다. docs/M3_28D.md 및 docs/M3_28R.md의 나머지 F1–F9는 그대로 적용한다. FIRST는 private Source이며 운영 S27/whole318/paid200은 그대로다. 이 문서는 private reflection을 조용히 추가하자는 허가가 아니다. 아래의 좁은 예외만 실제 Astra/max 리뷰 및 ROOT 반영 후 sole Sol R1에 적용한다.

관측: 실제 S27 owned recovery의 support/init은 완료됐지만 backend/schema/IO0이고, S28 FIRST의 ReadView는 모든 입력에서 false다. PSObject가 실제 거부 원인인지 아직 모른다. 따라서 Source/API 상의 경계와 actual runtime evidence를 구별한다. F3를 없애거나 canonical positive를 완화해서 PASS를 만들지 않는다.

선택한 방향은 CLR exact builtin과 exact engine PSObject에 한정한 읽기 전용 저장소 검사다. Public integrated member collection을 호출하지 않고, extension/type-name/adapter가 존재하는지를 그 저장소의 직접 읽기와 exact BCL identity lookup으로 판단한다. Instance/type-data extension 또는 unknown layout은 unsupported다. 기존 위험한 getter/adapter를 실행한 뒤 결과를 버리는 방식을 허용하지 않는다.

명시적으로 검토할 제한된 reflection 범위:
- typeof(PSObject) 및 그 Assembly에서 정의된 정확한 field metadata: _instanceMembers, _typeNames, _flags, _adapterSet, s_instanceMembersResurrectionTable, s_typeNamesResurrectionTable. Wrapper의 ImmediateBaseObject reference chain은8 hops 이하/ReferenceEquals cycle 거부 그대로다. Field 선언 Type/Assembly/static-instance/generic argument가 예상된 고정 shape와 정확히 맞아야 한다.
- Resurrection key는 실제 engine semantics를 고려한다. String/local-storage wrapper는 단순히 underlying string을 key로 삼으면 instance extension을 놓친다. 모든 wrapper layer의 기존 local storage와 해당 resurrection identity를 검사한다. 내부 GetKeyForResurrectionTables/Base를 무제한 호출하지 않는다. 제한된 chain에서 정확한 key를 계산하지 못하면 unsupported다.
- Exact System.Runtime.CompilerServices.ConditionalWeakTable의 TryGetValue만 정해진 identity key에 사용한다. Instance storage의 존재/내용 검사에서 사용자 PSMemberInfo.Value/Name/MemberType/Copy/Equals를 실행하지 않는다. Non-null collection을 무조건 empty로 보거나 처음32개만 보는 방식은 거절한다. 내부 collection의 정확한 backing storage 또는 검증된 engine/BCL count 접근만 허용하며 unknown collection/comparer/subclass를 거절한다. 입력 wrapper/cache/resurrection storage를 쓰거나 생성하지 않는다.
- Effective TypeTable도 확인한다. Bare base나 wrapper의 local instance members가 없다는 것만으로 TypeData/third-party adapter 부재를 주장하지 않는다. Source가 만든 임시 engine wrapper에서 고정 GetTypeTable read resolver를 사용하는 좁은 예외를 리뷰 대상으로 둔다. 기존 input의 InstanceMembers/TypeNames getter 또는 HasInstanceMembers의 cache 쓰기는 금지한다. Resolver의 정확한 DeclaringType/Assembly/signature를 확인하고 unknown은 unsupported다.
- Exact sealed engine TypeTable의 _extendedMembers 및 _typeAdapters 저장소에 고정된 CLR type hierarchy 이름만 lookup한다. Exact BCL ConcurrentDictionary<string,T>와 built-in ordinal comparer인 경우만 사용하고, user comparer/adapters/delegates/전체 arbitrary TypeTable 순회는 금지한다. Type hierarchy8 이하, string bound4096, wrapper8, map32, actual row bound를 넘지 않는다. Unknown or any nonempty applicable extension/adapter rejects before IO. 기본 Count alias 등 실제 미관측 항목에 대한 whitelist를 발명하지 않는다. 필요한 기본 metadata 예외가 드러나면 ROOT SECOND 이후 actual evidence를 바탕으로 판단하며 지금은 허용하지 않는다.
- Reflection은 위의 고정 field/identity lookup/resolver/count metadata에만 사용한다. Method 이름을 전역 검색해 임의 Type를 채택하지 않는다. GetMember/GetMembers/GetTypeNames/Member.Value/ToString/user getter/PSObject.AsPSObject(...).Members/TypeData normalization이나 setter는 없다. Runtime engine 및 BCL identity와 field/method shape는 실제 accepted owned metadata recovery 안에서 확인한다. Official master 분석을 설치 버전 증거로 승격하지 않는다. Runtime shape가 다르면 whole-old fallback이며 ROOT fast preadmission gate는 실패한다.

Sole R1은 viable shared ReadView를 구현한다. Bare null은 extension이 없으므로 그대로 인정하고 bool/int/long/double/string의 boxing/type를 보존한다. Map exact type/Keys/Count shadow·wrapped-key uncertainty·array rank1/lower bound0·schema/path literals 및 independent output arrays, Native error/read order는 그대로다. 캐시가 필요한 것은 고정 reflection metadata뿐이며 input/catalog row/file/raw/mtime/auth success를 저장하지 않는다. 안전한 shape 판정과 verifier 실제 field 접근이 서로 다른 규칙을 쓰면 거절한다.

원인을 관측할 필요가 있을 때 새 public diagnostic method나 Snapshot9 schema를 만들지 않는다. 고정 private rejection metadata(역할/row/key enum, CLR kind, depth, 고정 reason)에 한해 Supports가 자신의 thread-local storage를 갱신하고 owned K-CatalogVerified가 정확한 source-authenticated private field를 읽는 방안을 리뷰 대상으로 둔다. 최대 한 첫 거부, 문자열≤96 ASCII/숫자 bound, values와 arbitrary tree 없음, unknown private metadata는 diagnostic failure로 구분하고 primary error를 덮지 않는다. Existing authenticated support END journal에 bounded optional rejection만 넣을 수 있으며384/1152/524288 cap, ordinary old fallback, public3 signatures 및 existing7+digest/Snapshot9/prefix12는 유지한다. 이 최소 진단도 불필요하면 추가하지 않는다.
