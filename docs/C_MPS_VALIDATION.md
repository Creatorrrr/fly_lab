# C MPS 최적화 — 2026-09-09

Apple M1 Max에서 **PyTorch MPS + 사용자 정의 Metal 커널**로 전뇌 계산을 가속했습니다. 전체 뉴런과 연결, LIF 0.1ms, 물리 0.1ms, 제어 5ms를 그대로 유지했습니다. MuJoCo/FlyGym 몸 계산은 CPU에서 계속 실행합니다.

## 실측 결과

사용자가 실행하던 C_SHADOW 실험은 0.6모델초에 52.8729실제초가 걸렸습니다. 이 중 신경 계산 44.8835초, 물리 계산 7.6497초였습니다. [변경 전 상태와 측정값](../verification/c_mps_20260909/user_frame_before.json)을 저장했습니다.

아래 표는 같은 체크포인트에서 CPU와 MPS를 시작한 새 비교입니다. 이전 실행 수치와 다른 실험의 결과를 섞어 배속을 계산하지 않았습니다.

| 범위 | 모델 시간 | CPU 실제 시간 | MPS 실제 시간 | 향상 |
|---|---:|---:|---:|---:|
| 전뇌 단독, 동일 후각 입력, 3회 중앙값 | 0.05초 | 2.9473초 | 0.2549초 | **11.56배** |
| 사용자 C_SHADOW 상태의 실제 몸 연속 계산 | 0.1초 | 7.9524초 | 2.2229초 | **3.58배** |
| C_STRICT 직접 자극 상태의 실제 몸 연속 계산 | 0.1초 | 7.9149초 | 1.8210초 | **4.35배** |
| 실제 실행 서버, 같은 후속 상태, WebSocket 왕복 포함 | 0.05초 | 10.1326초 | 2.1200초 | **4.78배** |

[전체 보고서와 상태 원자료](../verification/c_mps_20260909/benchmark/report.json). 신경 측정은 첫 5ms 호출을 별도 기록한 뒤 같은 초기 상태에서 3번 실행했습니다. 물리 비교는 조건당 한 쌍의 짧은 실행으로, 장시간 처리량 보장은 아닙니다. 각 실제 시간에는 해당 호출의 신호 읽기와 프레임 구성이 포함되며 데이터 로드·몸 초기화는 제외했습니다. 동일 백엔드의 반복 신경 실행은 같은 상태를 생성했습니다.

**실시간 속도는 아닙니다.** 앞선 단독 물리 비교에서는 1모델초에 해당하는 계산량이 대략 18–22실제초 수준입니다. 신경 계산만 GPU로 옮겼으므로 CPU 물리 계산이 속도의 하한을 만듭니다. 더 큰 배속에는 몸 계산 경로의 별도 최적화가 필요합니다.

실제 브라우저를 켠 재생에서는 그보다 느린 **0.0154배속**이 관측됐습니다. 0.78모델초의 서버 측 누적 비용은 신경 12.4804초, 물리 28.8753초, 포트/감각 6.7895초였으며 모두 앞선 단독 실행보다 증가했습니다. 실행 시점의 시스템 부하와 상태에 따라 절대 시간이 달라지므로 단독 비교의 배속을 화면의 보장 속도로 제시하지 않습니다. [브라우저 재생 후 세부 측정](../verification/c_mps_20260909/browser_performance_readback.json).

이를 확인하기 위해 실제 서버에서도 동일한 후속 체크포인트를 CPU/MPS로 각각 복원해 비교했습니다. 50모델ms의 전체 왕복은 **10.1326초 → 2.1200초**였고 두 실행의 최종 위치·yaw가 동일했습니다. 이때 MPS의 물리 계산 1.1489초가 신경 계산 0.5427초보다 컸습니다. [실행 서버 대조 원자료](../verification/c_mps_20260909/server_backend_comparison.json). 이 수치도 한 쌍의 짧은 실행 결과입니다.

## 수치 검증

- 전체 139,255개 뉴런의 50ms 비교: 전압·지연 큐 차이 0, 전체 발화 수와 불응기 타이머 동일, 선택 집단 발화 시각 동일.
- 같은 비교의 발화율 최대 차이 **0.00000763Hz**, 시냅스 전류의 극미소 값 차이 약 `1.17e-38mV`. GPU의 float32 연산·극미소 수 처리 차이가 있으므로 모든 배열의 비트 단위 일치를 주장하지 않습니다.
- 실제 C_SHADOW 100ms: 몸 적분 상태와 궤적 모두 동일.
- 실제 C_STRICT 100ms: 위치 최대 차이 `4.91e-9mm`, yaw 차이 `1.70e-9rad`. 전체 물리 적분 벡터 최대 차이는 `0.002659`로 0이 아니며 위치 단위의 숫자가 아닙니다. 발화율 최대 차이 `0.00001526Hz`.
- 비교 전에 정한 신경 허용치는 전압·전류·큐 절대 오차 `1e-4`, 발화율 `1e-3Hz`이며, 발화 수·타이머·선택 발화 시각은 동일해야 합니다. 짧은 물리 비교의 위치·yaw 한계는 각각 0.01mm/0.01rad입니다.
- **전체 회귀검사 146/146 통과**, 그중 MPS 실장치 검사 8개. 발화·불응기·전도 지연, 억제/연결 차단 중 기존 도착 유지, 중복 pulse 대상, 구독 변경, GPU 저장·복원, CPU→MPS 상태 전환을 검사했습니다. [최종 검사 로그](../verification/c_mps_20260909/all_tests.log).

중복 pulse 테스트에서 처음에는 정렬한 입력 행렬이 비연속 메모리였는데 Metal 커널이 연속 행렬로 읽는 오류를 발견했습니다. GPU 입력을 C 순서의 연속 메모리로 만드는 수정 후 통과했습니다. [실패 로그](../verification/c_mps_20260909/mps_tests.log)와 [수정 후 로그](../verification/c_mps_20260909/mps_tests_after_contiguity_fix.log)를 함께 보존했습니다. 초기 두 커널 구현과 활성 행 최적화의 측정 기록도 별도 파일로 남겼습니다.

이 검증은 구현의 수치 일치성과 짧은 물리 연결 검사입니다. 생물학적 타당성이나 장시간 탐색 행동의 동일성을 보장하지 않습니다. 이전 C_STRICT의 자연 입력에 의한 지속 회전 문제를 이 최적화가 해결했다는 주장도 하지 않습니다.

## 변경 내용

`neural_mps.py`와 `lif.metal`은 MPS 장치에 연결망·전압·전류·발화율·지연 큐를 유지합니다. 매 tick에서 두 개의 순서가 있는 커널을 실행합니다.

1. 모든 뉴런의 LIF 상태를 갱신하고 발화를 판정합니다. 실제 발화한 뉴런의 출력을 받을 행에 정수 표시를 남깁니다.
2. 표시한 행만 원래 CSR 순서로 합산해 지연 큐에 저장합니다. 연결 입력이 없는 행에는 0을 저장합니다. 부동소수점 atomic 합산을 사용하지 않고 합산 순서를 유지합니다.

0.1ms 하위 단계에는 CPU로의 값 복사가 없습니다. 5ms 제어 경계에서만 감각 입력과 선택 출력·발화를 교환합니다. 모든 뉴런은 매 tick 계산하며, 발화하지 않은 뉴런이나 활성도가 낮은 영역을 모델에서 제외하지 않습니다. 미지 전달물질의 기존 마스킹 정책도 바꾸지 않았습니다. MPS의 float64는 지원하지 않으며 요청 시 명시적으로 거절합니다.

현재 설치한 PyTorch 2.14.0에서 희소 CSR 텐서를 MPS에 올리는 기본 연산은 `NotImplementedError`로 확인했습니다. 대신 공식 [`torch.mps.compile_shader`](https://docs.pytorch.org/docs/2.14/generated/torch.mps.compile_shader.html) API로 위 커널을 실행합니다. MPS의 장치 사용 방법은 [공식 문서](https://docs.pytorch.org/docs/2.14/notes/mps.html)를 참고했습니다. CPU fallback 환경변수는 사용하지 않았습니다.

화면에는 **신경 계산** 선택기를 추가했습니다. 장치 전환은 현재 상태를 체크포인트에 저장한 뒤 별도 인스턴스로 옮겨, 모든 신경 상태 배열이 동일한지 확인한 후 적용합니다. 진행 중인 기록은 장치를 섞지 않도록 먼저 종료해야 합니다. 전환 실패 시 기존 실험을 유지합니다. 새로고침은 실행 중인 실험에 다시 연결하고, 사용자가 **새 실험**을 눌렀을 때만 초기화합니다.

실제 브라우저에서 재생·일시정지와 기존 실험 재연결, CPU→MPS 장치 왕복 전환을 확인했습니다. 왕복 중 모델 시간은 1.480초로 유지됐고 마지막 화면은 **LOCAL · MPS / PHYSICS**, 일시정지 상태입니다. 조회한 브라우저 오류 로그는 없었습니다. [화면 검증 기록](../verification/c_mps_20260909/browser_verification.json).

MPS 재생은 응답당 10모델ms로 더 자주 화면을 갱신합니다. 신경·물리 tick이나 실제 모델 시간은 생략하지 않습니다. 속도 표시는 복원 이전 시간을 배속으로 잘못 계산하지 않도록, 현재 장치에서 실제 계산한 모델 시간만 사용하고 프레임 신호 읽기 비용도 포함합니다.

## 실행과 재현

```sh
.venv/bin/python -m pip install -r requirements-mps.txt
.venv/bin/python run_c.py --doctor --backend exp_lif_mps
./launch_mps.sh
```

화면의 **신경 계산 → MPS · Apple GPU**로도 전환할 수 있습니다. CPU 기준 실행은 기존 `./launch_c.sh`를 사용합니다. MPS가 없으면 명확히 오류를 표시하며 CPU로 조용히 대체하지 않습니다.

```sh
.venv/bin/python tools/benchmark_c_backends.py \
  --checkpoint artifacts/c/checkpoints/before-mps-20260909 \
  --strict-checkpoint verification/c_local_20260909/acceptance/active_checkpoint \
  --out verification/new_mps_benchmark
```

기존 출력 디렉터리는 덮어쓰지 않습니다. 데이터·모델 해시는 C 기준선과 동일하며 GPU 런타임 버전과 shader 해시는 각 MPS 체크포인트에 저장합니다. [실행 환경 확인](../verification/c_mps_20260909/mps_doctor.json), [현재 실험 전환 확인](../verification/c_mps_20260909/live_transfer_result.json), [전체 변경 전 소스 체크섬](../verification/c_mps_20260909/source_before.sha256)을 보존했습니다.
