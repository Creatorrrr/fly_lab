# E233 startup 기준 필드 정정

E233 저장분석과 부모 독립 수식 검산184개는 완료했지만, 출력의 startup 수치는 기존 E225 수치와 달랐다. 추가 소스 대조에서 **부모 E232 설계 자체가 잘못된 기준 필드 `recorded_command[1:100]`를 지정**한 사실을 확인했다. 실제 기존 startup은 E197 `loaded_startup_target_command`(99×42), tendon은 `loaded_startup_target_tendon`(99×6)이다. 근거는 `parent-e225-startup-addendum-audit.py`와 E225 고정 판정이다. 이는 Sol 구현 불일치가 아니라 부모 설계·검토 오류다.

완료된 E232/E233 설계·소스·결과·원본 비용은 수정하지 않는다. E233 원본 startup 표와 그에 의존한 분기는 **기존 startup 계약 판정으로 유효하지 않음**을 명시한다. 4성분 합성, 양쪽 canonical 경로, 첫 tick·기억·출력 차이,6D 투영거리 검산은 이 잘못된 기준 필드와 독립적이다.

같은 Sol 첫수정 뒤 SECOND에서 남은 정정이므로 현재 세션이 처리한다. `parent-e233-startup-correction.py`가 저장된 actual/conditional와 네 command 성분을 그대로 두고, 기존의 정확한99행 기준에 대한 두 후보 및 대수적 성분 제거의 RMS/max와 위치를 한 번 재계산한다. 한 후보만 다른 기준으로 재평가하지 않는다. 기존 E225 actual RMS/max와 E218 conditional 기대값을 재현해야 한다. q .018/.04와 LTM .009/.025 한계를 바꾸지 않는다. 기존 부정결과를 보존하고 신체·학습·신경/CUDA/원본재실행0이다. 두 감각 기억의 차이는 입력 인과를 직접 입증하지 않는다.

이 정정은 CPU1의 저장 검산으로 별도 계측한다. 원본 감독누적6090.0136165996555/6119초와 잔여28.986383400344494초는 유지한다. 추가 비싼 실행은 원래 기준 복원과 결과 검토 이후 별도 사전 설계로 결정한다. F1–F8 미완료, F6미노출, E150최선/M2/UI 보존.
