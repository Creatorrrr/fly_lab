## 4. C.1: 재현된 결함 수정과 배포 기반

### R1. 오류 이후 새 실험을 시작할 수 있게 만들기

현재 [server.py](../flylab/c/server.py)의 init은 이전 엔진의 checkpoint() 성공을 요구한다. [engine.py](../flylab/c/engine.py)는 오류 상태의 체크포인트를 거절한다. 이번에도 허용 범위의 100mV 자극 11개를 동일 뉴런에 중첩하면 계산 오류 후 새 실험이 다시 실패했다.

구현:

1. 정상 체크포인트와 오류 진단 덤프를 서로 다른 스키마·폴더·목록으로 분리한다. 오류 덤프에는 `restorable=false`, 오류 원인, 마지막 정상 경계 tick, 몸/신경/인코더 시각, 입력·활성/예약 개입, 데이터·모델·장치 해시를 남긴다. NaN/Inf·읽기 실패 필드는 유효한 JSON 표현과 읽기 실패 정보로 보존한다.
2. 정상 실험은 현재의 자동 체크포인트를 유지한다. 오류 실험에서는 진단 덤프를 남기고 새 인스턴스 생성을 허용한다. 오류 상태를 정상 체크포인트처럼 저장하거나 오류 플래그만 지워 재생하지 않는다.
3. 새 엔진의 생성·기본 프레임·필요 프로파일 검증까지 성공한 뒤 포인터를 교체하고 이전 몸/장치를 정리한다. 새 생성 실패 시 후보 자원을 닫고 기존 인스턴스·오류 자료를 유지한다. 기존 인스턴스 close 실패도 새 실행을 잃지 않도록 별도 진단한다.
4. 실행 중 기록이 오류를 만나면 마지막 유효 tick까지 FAILED로 마감하고 청크·이벤트를 유지한다. 신경 오류, body.fault만 설정되는 경로, 저장 오류를 모두 다룬다.
5. 디스크 쓰기 실패가 다시 복구를 영구 차단하지 않게 오류 내보내기 실패를 응답에 명시하고 최소 진단을 메모리에 남긴다. 정상 실험의 자동 저장 실패와 오류 실험의 긴급 재초기화 정책을 구분한다.
6. 응답에는 새 실험 ID, 이전 체크포인트 또는 진단 ID, 복구 종류와 저장 결과를 넣는다. 화면은 서버의 성공 응답 이후 현재 실험 표시를 바꾼다.

대상: server.py, engine.py, storage.py, 필요 시 새 fault-report 모듈, src/c/app.js, tests/test_c_delivery.py 또는 새 오류 복구 테스트.

완료 기준: 정상 init, 신경 오류 후 init, 몸 오류 후 init, 기록 중 오류 후 init, 새 몸 생성 실패, 진단 저장 실패, 장치 작업 정리 실패를 검사한다. 실패한 새 생성에서 기존 인스턴스가 닫히지 않고, 복구 성공 후 재생·일시정지·체크포인트가 다시 동작해야 한다. 마지막에는 별도 실제 MuJoCo 서버와 브라우저에서 복구 흐름을 확인한다.

### R1a. 중첩 자극의 합산 입력과 시간 일관성

개별 자극 범위는 ±100mV지만 backend의 drive 범위는 ±1000mV다. 예약 단계는 합산을 검사하지 않는다. **이번 CPU 재현에서는 control/neural tick이 0인데 FixtureBody의 시간만 0.005초 진행했다.** CPU는 몸을 진행한 뒤 neural.advance()에서 입력을 검증하고, MPS 경로는 begin_advance()가 몸 진행 전에 호출된다. MPS의 같은 반례는 이번에 새로 실행하지 않았으므로 동일 결과로 보고하지 않는다.

구현:

- 뉴런 ID별 활성 구간을 반열림 구간 `[start_tick, end_tick)`으로 계산하고 예약·취소·만료 시 합산 자극을 검사한다. 동일 경계에서 끝나는 자극과 시작하는 자극을 정확히 처리한다.
- 현재 포트의 감각 drive와 개입 drive를 합친 실제 입력을 **몸 또는 신경을 진행하기 전에** 공통 함수로 검증한다. 이벤트 serial, 인코더 필터/RNG, 활성 목록도 거부 시 보존되도록 준비/검증/확정 단계를 나눈다.
- 포트 cap을 이용한 예약 시 상한 진단은 실제 실행 경계 검증과 구분한다. 미래 감각값을 모르므로 예약 검사만으로 안전성을 보장하지 않는다. 상한에 가까운 입력을 임의로 잘라 성공시키지 않는다.
- Poisson pulse와 지속 drive는 서로 다른 입력 경로다. 중복 pulse 대상 합산·유한값·형상·단위·수치 한계를 별도로 명시한다. 지속 drive의 1000mV 한계를 근거 없이 pulse나 재귀 시냅스 전류 전체에 그대로 적용하지 않는다.
- GPU 작업 제출/완료 및 물리 중간 실패의 부분 진행은 진단에 남긴다. 제어 구간 전체를 매번 복사해 되돌리는 방식은 비용을 먼저 측정하고 필요 여부를 결정한다. 입력 거부의 무부작용과 계산 중 물리 고장의 복구 가능성을 혼동하지 않는다.

완료 기준: 양·음 중첩, 1000 경계, 실제 감각 drive 추가, 다른 대상, 비중첩 시간, 취소·만료, 복원한 예약, 중복 pulse를 검사한다. 사전 검증 거부 시 몸/신경/인코더/개입 상태·시각이 그대로여야 한다. 정상 입력의 기존 스파이크·지연 큐·보행 결과는 유지한다.

### R2. 전뇌 검증 판정 바로잡기

[verify_c.py](../tools/verify_c.py)는 제공된 그래프가 무엇이든 500스텝 계산 후 full_brain_compute를 PASS로 표시한다. 이번 6개 뉴런 회로도 `graph.full_brain=false`인데 CLI 종료 코드 0과 같은 PASS가 나왔다.

구현할 판정:

| 검사 | 질문 | 필수 증거 |
|---|---|---|
| loaded_graph_compute | 입력된 그래프를 실제 계산했는가 | 상태 배열 크기, graph hash, 실제 tick·backend, 수치 유효성 |
| full_snapshot_membership | 선언한 스냅샷의 원본 목록을 모두 포함했는가 | 고정 원자료 제품/해시, roster ID 집합 비교, 누락·추가·중복·제외 목록 |
| full_snapshot_compute | 전체 포함 그래프를 실제로 계산했는가 | 앞의 두 검사 + 실제 계산 노드 수·상태·tick 일치 |
| closed_loop_contribution | 선택한 C 출력이 실제 몸에 기여했는가 | MuJoCo 실행·동일 초기 상태의 운동 연결 차단 대조 |
| task_behavior | 해당 과제를 충족했는가 | 8절의 기간·관측 품질·행동 기준 |
| backend_equivalence | 해당 장치 경로가 비교 기준을 충족했는가 | 장치 실제 실행·조건·오차·발화 비교 |

GraphStore.full_brain 플래그 사용은 최소 수정이다. 현재 플래그도 선언된 metadata를 확인하므로, 독립적인 원본 roster 또는 검증된 데이터 manifest와 대조하는 완결된 경로까지 추가한다. 139,255라는 숫자만 맞거나 자체 선언한 full_snapshot만으로 승인하지 않는다.

CLI에는 요청한 검증 범위와 필수 gate를 명시한다. 제안 종료 코드는 필수 검사 모두 충족=0, 실패=1, 필수 환경/자료 미확보 또는 불완전=2다. 선택하지 않은 GPU 검사는 NOT_RUN으로 남길 수 있지만, 요청한 MPS/CUDA/full-snapshot/물리가 BLOCKED인데 성공 종료하지 않는다. fixture 계산의 성공과 full-snapshot 요구 실패를 구분한다. 기존 보고서는 덮어쓰지 않고 새 스키마로 기록한다.

검사: 6개 fixture, 재배선 control, roster 일부 누락, 같은 수의 다른 ID, 잘못된 원자료 해시, 미확보 원자료, 잘못 선언된 snapshot, 고립 뉴런, 실제 고정 bundle. 재배선은 모든 뉴런을 계산해도 원래 연결망 검증 PASS를 받을 수 없다.

### R3. 새 환경 설치·데이터 재구성·프로파일 선택

현재 문서 명령은 저장소에 이미 있는 bindings.json을 다시 만들려고 하며 불변 출력 정책 때문에 실패한다. 이번에도 종료 코드 1과 `Binding profiles are versioned; choose a new output path`를 확인했다.

또한 **유효한 bindings.json 옆에 다른 graph_hash를 가진 bindings-*.json 하나가 있으면 유효한 파일을 명시해도 초기화가 실패**한다. profiles()가 형제 파일을 일괄 검증하며 예외를 전파하기 때문이다.

구현:

1. 실행 경로를 두 가지로 문서화한다. “기존 고정 원자료·bundle·binding으로 재현”과 “새 자료를 받아 새 버전을 생성”이다. 새 경로 예시는 data/acquisitions/<새 획득 ID>/raw, bundle, bindings.json이다. 기존 출력 덮어쓰기나 수동 graph_hash 치환은 안내하지 않는다.
2. 기본 graph/binding의 배포 manifest와 소스 해시를 함께 제공한다. 새 다운로드 결과가 달라지면 원자료 해시, roster, 주석, 쌍 연결, 가중치·정책, 실제 배열 dtype/order 차이를 비교하는 보고서를 만든다. 외부 리뷰에서 달라진 graph hash의 정확한 원인은 두 manifest를 확보하기 전 단정하지 않는다.
3. 빌더의 고정 문자열 `Codex static acquisition 2026-09-09`를 명시적 획득 metadata로 바꾼다. 새 스키마는 정렬된 ID/주석, 고정 dtype·byte order의 연결/가중치, 모델 정책으로 내용 신원을 계산하고 획득 시각·설치 경로는 별도 provenance로 둔다. 같은 고정 원자료·주석·정책 재빌드는 같은 내용 신원을 내야 한다. 원본 gzip 바이트 해시도 별도로 유지한다. 기존 graph_hash와 체크포인트의 호환성 검사는 그대로 보존하고, 새 해시가 비슷하다는 이유로 구형 체크포인트 검증을 우회하지 않는다.
4. 작은 raw manifest·bundle identity/manifest 또는 동등한 배포 provenance는 추적 가능하게 제공한다. 대용량 배열·원본은 릴리스 자산으로 관리할 수 있다.
5. 프로파일 목록은 유효/비호환/손상과 이유를 개별 표시한다. 선택하지 않은 비호환 파일 때문에 정상 실행을 막지 않는다. 명시적으로 선택한 비호환 파일은 계속 거절한다. 발견 대상 16개 제한과 캐시 규칙도 공개한다.
6. 동일한 이름의 다른 파일을 조용히 혼용하지 않도록 profile ID, 내용 해시, graph hash를 사용한다. 체크포인트는 정확한 binding hash가 있어야 복원하며 가장 가까운 다른 프로파일로 바꾸지 않는다.
7. CPU·macOS MPS·Linux CUDA별 실제 검증한 의존성을 lock 또는 설치 제약 파일로 고정한다. 현재 SciPy/NumPy 등의 범위 설치만으로 같은 환경이 재현된다고 설명하지 않는다.

대상: tools/build_c_graph.py, build_c_bindings.py, build_c_odor_profile.py, flylab/c/graph.py·server.py, launch_c.sh/launch_mps.sh, docs/C_ARCHITECTURE.md, README.md.

완료 기준: 깨끗한 checkout의 고정 재현, 새 획득 디렉터리 빌드, 기존 출력 보존, 예상치 못한 해시 변경 설명, 비호환 형제 파일과 정상 파일 공존, 정확한 프로파일로 체크포인트 복원. 네트워크 차단은 데이터 BLOCKED로 남기며 다른 데이터나 fixture로 대체하지 않는다.

### E1. 검증 원자료를 외부에서도 확인 가능하게 만들기

제안 산출물은 작은 **evidence index**와 불변 검증 패키지다.

- index: 소스 커밋/변경 패치 해시, graph/binding/model/body/environment/runtime 해시, 명령, 플랫폼·장치, 실행 일시, 실제 모델 시간, 검사별 pass/fail/skip, 기술/과제/생물학 상태, 원자료 URL·바이트·SHA256.
- 패키지: 로그, 보고서, 조건별 trace, 필요한 초기/최종 체크포인트, 기록 manifest/청크·이벤트, 버전·shader 해시, 브라우저 readback. 과거 실패·차단·불확정 결과도 포함한다.
- 소스 체크섬과 생성 자산 체크섬을 별도 목록으로 제공한다. 패키지 재생성과 업로드 때 자기 자신을 해시에 포함하는 순환 구조를 피한다.
- 로컬 기존 54조건 자료와 외부 8조건 자료는 별도 실행 ID로 유지한다. 외부 생성 첨부 파일을 확보하기 전에는 리뷰 본문만 evidence_type=review_report로 표시한다.
- 릴리스 자산 또는 장기 보존 저장소에 연결하고, 새 checkout에서 index 다운로드→SHA 검증→보고서/필수 trace 열기→필수 재현 명령 실행을 검사한다. 오래된 CI 임시 링크만 남기지 않는다.

완료 기준: 외부 검토자가 세 개 누락 provenance 파일과 인용된 C/MPS 결과를 확인할 수 있고, 빠진 파일은 검증 실패로 드러난다. 외부의 건너뛴 GPU 검사와 로컬 GPU 검사가 구분되어야 한다.

## 5. C.2: 감각 입력과 자연 행동 개발

### N1. 실패 원인을 단계별로 분리하는 진단기

현재 증상만 보고 gain 또는 연결을 한꺼번에 조정하면 어떤 경로가 행동을 만든 것인지 확인하기 어렵다. 먼저 새 `tools/diagnose_c_pathways.py`와 기계 판독 보고서를 만든다.

입력은 graph/binding 해시, 고정 감각 시퀀스, 기간, seed, backend다. 출력은 원시 좌우 센서·포화 비율·포트 입력, 감각 뉴런 및 하행 집단의 전압/발화/발화율, 디코더의 제한 전후 값, 몸의 실제 전진축 이동·회전·접촉, 단계별 시각이다.

진단은 다음을 나누어 수행한다.

1. 해부학 연결과 유효 가중치 그래프 각각에서 감각 집단→하행 출력의 도달 가능성·마스크 영향을 조사한다. 정적 경로 존재가 실제 발화 전파를 보장하지 않는다고 표시한다.
2. 무입력, 동일한 양측 입력, 좌/우 단독, 강도 변화, 위험 단독, 감각 차단, 직접 출력 자극을 고정 입력으로 실행한다. 신경→출력 검사는 먼저 몸 없는 open-loop에서 원인을 분리한다.
3. 전체 뉴런 상태 계산 여부와 실제 활성 뉴런 수·집단별 전파를 함께 기록한다. 정지한 뉴런을 계산에서 삭제하지 않는다.
4. 기준선·연결 구조 대조에는 기존 [c_topology_control.py](../tools/c_topology_control.py)를 확장해 사용한다. 이 도구의 NT 집단 내 presynaptic identity permutation이 보존하는 것과 바꾸는 것을 명시하고, 이를 일반적인 degree-preserving 무작위화로 이름 붙이지 않는다.
5. 동일 감각 입력 대조와 폐루프 대조를 분리한다. 폐루프에서 궤적이 달라지면 이후 센서가 달라지는 것은 정상이다. 원래 연결이 반드시 더 우수하다는 판정은 미리 넣지 않는다.

완료는 자연 탐색 성공이 아니라 재현 가능한 원인 분리 보고서다. 몸 움직임을 얻기 위한 숨은 상수 전진 출력은 넣지 않는다. 배경 발화 또는 생리 상태가 필요하다는 가설은 근거·새 모델 버전·차단 대조를 갖춘 별도 실험으로 다룬다.

### N2. 좌우 후각·위험 냄새 프로파일 보완

기존 양측 68개 및 39개 입력 연결 자체를 다시 만드는 작업이 아니다. 감각장·인코더·출력 반응을 보완하고 자연 행동 기여를 검증한다.

- 기존 평균 냄새와 bilateral-geosmin-v1은 재현 기준선으로 보존하고 새 profile v2를 만든다.
- 원시 냄새장, 센서 clipping, 인코더 gain/cap/filter, neural rate, motor clipping 중 어느 단계에서 좌우 정보가 사라지는지 각각 측정한다.
- 낮은 농도부터 포화 구간까지 강도와 거리 스윕을 한다. 좌우 대칭 환경과 실제 머리/감각 위치를 사용하고, 좌우 주석·신경 투사 검토를 기록한다. 좌우 soma 표기를 말초 입력 위치의 완전한 증거로 취급하지 않는다.
- 식품 냄새와 geosmin을 대표하는 가상 위험장을 특정 실험 자극으로 명시한다. 범용 위험 신호와 동일하다고 일반화하지 않는다. 위험 입력은 현재 머리 중앙의 양측 scalar이므로 좌우 방향 정보 추가는 센서 모델·근거 검토를 먼저 거친다.
- 농도 단위와 mV/Hz 입력의 변환·포화·필터를 문서화한다. 표준화된 환경 단위가 생물학적 농도로 보정되지 않았다면 공학적 단위를 유지한다.
- 변경한 조건은 개발용 seed/환경에서 조정하고 평가용 조건에는 고정한다. 실패한 profile은 이름과 해시를 남겨 보존한다.

완료 기준: 대칭/비대칭 자극이 인코더에서 의도대로 구별되고 입력 차단이 해당 입력을 없앤다. 이어서 발화·하행 출력·몸 변화의 인과적 기여를 보고한다. 포트가 켜졌다는 사실만으로 먹이 접근·위험 회피를 통과시키지 않는다.

### N3. 접촉·시각·자기 운동 정보 연결

추가 우선순위는 장애물 과제에 필요한 기계 감각/접촉 검토, 제한된 시각 입력, 자기 운동 정보 순으로 제안한다. 실제 대상 ID가 확보되는 순서에 따라 조정할 수 있다.

| 채널 | 필요한 개발 | 생물학적 경계 |
|---|---|---|
| 접촉·기계 감각 | 접촉 위치/방향/크기를 구분하는 관측, 감각 유입 ID·지연·입력 단위, 접촉 차단 대조 | 다리 고유수용성 정보가 VNC 내부에서 처리되면 FAFB만으로 직접 복원할 수 없음. 검토된 뇌 유입 경계나 명시적 engineering proxy로 한정 |
| 제한된 시각 | 실제 몸 기준 시야, 가림, 좌우·방위 대응, 시간 필터, 검토된 입력 뉴런 ID | 64개 ray를 임의로 임의 뉴런에 연결하지 않음. 제한된 시각 proxy와 실제 복안 재현을 구별 |
| 자기 회전·속도 | 관측에 있는 신호의 감각 유입 경로 검토, 단위·좌우 부호·지연 | 세계의 정답 yaw/목표 방향을 디코더에 직접 전달하지 않음 |
| 근접 거리 | 현재 ray 거리와 실제 이용 가능한 감각 신호의 대응 검토 | 직접 거리 센서가 있다는 생물학적 주장 금지. proxy라면 독립 프로파일로 공개 |

각 매핑에는 dataset/specimen/snapshot, 실제 문자열 ID, 세포형·afferent 근거, 좌우 방향, 출처, 전류/발화율 변환, 불확실성, 검증 상태를 저장한다. 미확정 매핑은 UNBOUND/BLOCKED_MAPPING으로 남긴다. 미확정 채널을 자동 대체해 C_STRICT 회피 성공을 만들어 내지 않는다.

완료 기준: 알려진 센서 자극→대상 뉴런 입력, 잘못된 ID/측/graph 거부, 단위·인과적 시간 지연, 센서 차단·뉴런 출력 차단, 실제 장애물 이동의 감각 반영. 각 과제에 필요한 포트가 검증된 이후에만 8절의 행동 평가로 넘어간다.

## 6. M1: 실제 운동 출력 검증과 수정

현재 8개 하행 뉴런 readout은 시작점이며 stop 집단은 비어 있다. 전진·후진·회전 변환은 소수의 발화율 평균과 gain·clipping을 사용한다. 후보 수를 늘리는 것보다 현재 readout과 실제 다리 제어 사이의 관계를 먼저 확인한다.

구현·검증 순서:

1. 신경망과 별도로 MotorAdapter/HybridTurningController에 선언된 전진·후진·좌우·정지 요청을 입력한다. 이 시험으로 **몸 어댑터 자체가 요청한 움직임을 낼 수 있는지** 확인한다.
2. 실제 하행 뉴런 직접 자극→발화율→제한 전후 운동 명령→다리 구동→실제 이동을 검사한다. MDN 자극의 음수 요청과 후진한 몸 궤적을 분리한다.
3. 후보 집단·출력 측·정지 집단은 자료와 문헌을 검토해 별도 binding 버전으로 만든다. stop 집단을 이름만 그럴듯한 뉴런으로 채우지 않는다.
4. 몸 회전 중 이동을 전진으로 오인하지 않도록 매 시점 실제 몸의 전방 축에 투영한 부호 있는 변위를 사용한다. 회전량·수평 순변위·왕복 누적 경로도 함께 기록한다.
5. gain·필터·포화 개선은 먼저 실제 발화 동작 범위와 몸의 응답 곡선으로 보정한다. rate decoder의 변경과 LIF/연결 가중치 변경을 같은 실험에서 동시에 하지 않는다.
6. 직접 출력 자극 검사 통과 후 자연 감각만 사용하는 C_STRICT에서 재검증한다. C_ASSISTED 보조 및 C_SHADOW B 출력은 각각 다른 대조로 남긴다.

초기 공학적 인수 기준 제안은 8절에 포함한다. 이는 실제 초파리의 운동 성능을 그대로 재현했다는 생물학적 기준이 아니다. 저수준 후진 패턴을 수정할 경우 기존 B_COMPAT·접촉·외력·복원 검사를 필수로 다시 수행한다.

## 7. V1/U1: 장시간 캠페인과 관측·평가 체계

### 충분한 길이의 실행기

현재 paired()/paired_campaign()은 한 실행 10모델초, 요청 전체 20모델초로 제한한다. 단순히 UI의 기간 입력 상한을 늘려 30–120초 캠페인을 요청하면 현재 서버 구조·메모리·응답 시간과 맞지 않는다.

- 새 `tools/run_c_campaign.py`와 재사용 가능한 campaign runner를 만든다. 기존 짧은 paired API는 유지한다.
- 제어 구간을 작은 청크로 진행하고, 조건별 진행·취소·오류·완료와 마지막 정상 checkpoint를 기록한다. 초기 구현은 독립 CLI 실행으로 사용자 실험과 분리한다.
- UI 연결 단계에서는 작업 ID로 시작/조회/취소하는 비동기 인터페이스를 추가한다. 사용자 재생 실험과 캠페인은 상태를 공유하지 않는다. CPU/GPU 동시 점유로 성능 비교가 오염되지 않도록 비교 실행은 독점 worker에서 순차 수행한다.
- 재개는 같은 graph/binding/model/body/runtime 신원이 확인된 마지막 정상 상태에서만 한다. 중간 고장 이후의 불완전 상태로 연속 실행했다고 보고하지 않는다.
- 원시 기록은 청크로 쓰고, 화면용 버퍼만 제한한다. 과학적 이벤트·개입·샘플을 조용히 버리지 않는다.
- `current checkpoint 반복`은 결정론 검사, `fresh seed 반복`은 다른 초기 조건 검사로 구분한다. seed만 달라도 환경·입력이 결정론적으로 같으면 독립 행동 표본으로 과장하지 않는다.

### 행동 판정 공통화

현재 tools/navigation_checks.py는 모델 시간 기반 창이고 flylab/c/behavior.py는 별도의 5ms 표본 기준 계산이다. 버전별 기준이 어긋나지 않도록 공통 평가 모듈 또는 명시적 adapter를 사용한다.

- stuck_window, extent, 최대 관측 공백, resume deadline·순변위·전방 이동을 정책 객체에 모은다. 기존 B 판정은 회귀 자료로 보존한다.
- 관측 공백·잘못된 tick·기간 부족·운동 차단 구간에는 INCOMPLETE 또는 NOT_APPLICABLE을 사용한다. 유효한 평가 창이 없는데 NOT_DETECTED/PASS를 부여하지 않는다.
- C_STRICT에는 보조 회피 flag가 없으므로 **실제 장애물과의 접근·접촉·이탈 사건**으로 평가를 정의한다. 기존 보조 제어의 flag 해제를 C 신경망의 회피 완료 조건으로 재사용하지 않는다.
- 회피 후 2초의 충분한 관측을 확보한다. 회피 직후 실행이 끝나면 성공으로 처리하지 않는다.
- 의도적인 정지 여부는 과제의 사전 정의된 구간/상태로 결정한다. 출력이 0이라는 이유로 motion_expected를 자동 해제하지 않는다. 먹이 도착 이후 체류 구간 등은 시작 전 과제 계약에 넣는다.
- 원시 5ms 접촉 표본보다 짧은 충돌을 중요하게 평가한다면 물리 substep의 접촉 이벤트/최대 충격을 별도 집계한다.
- 기술 상태, 과제 상태, 생물학 검증을 분리한다. 개입 전 동일성은 paired의 필수 조건이고, 성공률은 모든 유효/실패/불완전 표본 수와 함께 표시한다.

### UI에서 추가할 상태

현재 실행 모드, 새 실험 설정, 최종 명령 출처, 연결된 감각과 미지원 감각, 감각/출력 포화, 오류 복구 결과, 작업 진행·취소·불완전 이유를 표시한다. C_SHADOW의 보행을 C 신경 제어로 오인할 수 없게 “몸 구동: B / C 계산 중”을 함께 보여준다. C_STRICT는 보조가 없다는 뜻이며 생물학적 승인 배지가 아니다.

## 8. 과제·수치·물리 인수 기준과 캠페인 설계

### 개별 과제 기준 초안

아래 수치는 기존 고착 정책과 해석 가능한 이동량에 기반한 **공학적 출발안**이다. 파일럿 전 criteria 파일에 값·과제 정의를 고정하고, 수정하면 새 버전과 수정 이유를 남긴다. 평가용 조건을 본 뒤 통과하도록 기준을 바꾸지 않는다.

| 과제 | 필수 관측·제안 기준 | 인정하지 않는 대체 증거 |
|---|---|---|
| 기술적 실행 | 오류 0, tick 일치, 필수 샘플 누락 0, 올바른 실제 backend | 프로세스 생존 또는 GPU 코드 존재 |
| 지속 전진 | 이동을 요구하는 10초 구간에서 수평 순변위와 부호 있는 전방 이동 각각 5mm 이상, 유효한 3초 창에서 위치 범위 대각선 1mm 미만 고착 없음 | 회전 중 누적 경로 길이만 증가 |
| 좌우 조향 | 거울상 조건에서 요청·실제 yaw 방향을 확인하고 전진 성분과 분리. 허용 오차·회전량은 몸 단독 응답 검사 후 고정 | 좌·우 rate 차이만 확인 |
| 후진 | 안정된 시작 상태의 2초 자극 구간에서 몸의 전방 축 투영 누적 이동 -1mm 이하. 접촉/넘어짐·과도 회전도 기록 | 음수 forwardSpeed 또는 거리 크기 0.195mm |
| 정지 | 보행 중 선언된 정지 자극 후 0.5초 안정화, 다음 1초 수평 이동 0.5mm 이하. 해제 후 2초 내 순변위·전방 이동 각각 1mm 이상 | 멈춰 있던 모델에 다시 0 명령 |
| 먹이 접근 | 시작 시 먹이 밖에서 30초 이내 지정한 냄새원 중심 2mm 영역 진입. 도달 시간·거리 감소·도착 뒤 체류를 분리 | 강한 냄새 입력, 입력 뉴런 발화 또는 구동값 증가 |
| 위험 회피 | 같은 시작 상태의 위험 없음/있음·감각 차단 대조. 위험 영역 체류·진입 감소와 목적 있는 이동을 함께 평가 | 처음부터 정지해 위험원에 접근하지 않음 |
| 장애물 회피 | 실제 접근 기회가 있는 배치, 중대한 몸 충돌/넘어짐/고착 없음, 실제 이탈 후 2초 내 순변위·전방 이동 각각 1mm 이상. 지지 발 접촉과 몸 충돌 구분 | C_ASSISTED 보조가 대신 회피, 회피 flag 해제만 관찰 |

위험 회피의 위험 영역·최소 진행량과 조향 허용치는 감각/몸 단독 진단 후 **평가 시작 전에** 정한다. 단일 고착 검사를 모든 행동의 성공 기준으로 사용하지 않는다. 생물학적 재현을 주장할 때는 실제 초파리 실험의 자극·조건·행동 정의·수치 자료와 별도로 비교해야 한다.

### 실행 단계

| 단계 | 설계 | 목적 |
|---|---|---|
| 짧은 회귀 | 기존 0.2/0.3초 조건과 기준 checkpoint | 새 결함 수정이 기존 수치·물리 계약을 깨지 않았는지 확인 |
| 입력·출력 진단 | 감각 강도/좌우·직접 출력 자극. 짧은 구간에서 시작해 2–10초로 확장 | saturation·전파·readout·몸 원인 분리 |
| 개발 파일럿 | seed 7/19/42 × 6장면 × 3모드 × 10모델초 = **54실행, 540모델초** | 기준선·좌우 먹이·좌우 위험·정면 장애물에서 지원 범위와 실패 확인 |
| 고정 조건 평가 | 별도로 고정한 10개 초기 조건 × 6장면 × 3모드 × 30모델초 = **180실행, 5,400모델초** | 자연 행동·실패율·보조 기여·환경 일반화 평가 |
| 인과 대조 | 동일 초기 checkpoint에서 감각 차단, 운동 차단, 선택 하행 억제, 보조 차단, 연결 구조 대조 | 신경·감각·보조의 기여 분리 |
| 내구성 | 과제를 통과한 프로파일을 고정하고 seed/환경 3조건에서 각 120모델초 | 고착·메모리·기록·장치 상태·복원 문제 확인 |

여섯 장면은 기준선, 먹이 좌/우, 위험 좌/우, 정면 장애물이다. 모드는 C_STRICT/C_SHADOW/C_ASSISTED다. 시각·접촉 포트가 미지원인 프로파일의 장애물 성공을 승인하지 않는다. 파일럿 결과가 불완전하면 전체 180실행에 바로 들어가지 않고 해당 원인을 먼저 해결한다. 옛 54실행×0.2초와 새 54실행×10초는 별도 캠페인 ID다.

고정 조건에는 seed 외에도 시작 위치·방향, 냄새원 거리·강도, 좌우 거울상, 마찰을 포함한다. 초기 위치 변경 인터페이스가 없으면 테스트 환경 생성 기능부터 추가한다. 평가용 조건 목록은 파일럿 조정과 분리해 고정한다. C_STRICT의 특정 과제 “지원” 표시는 예를 들어 고정 10조건 중 8조건 이상 성공을 초기 공학적 목표로 제안하되, 개별 실패와 신뢰구간을 함께 보고하고 실제 생물학적 강건성으로 일반화하지 않는다.

운동 차단/뉴런 억제 대조는 개입 시점 이전 상태가 같아야 한다. 감각 변화는 입력, 발화, readout, 몸 중 어느 단계에 차이가 발생했는지 보고한다. 자연 행동을 개선했다는 주장은 기준 프로파일과 짝지은 비교로 평가하며 효과가 불확정이면 그대로 남긴다.

실행 비용은 파일럿에서 측정한 `SIM/WALL` 비율 r로 `전체 모델 시간 / r + 로딩·컴파일·저장 비용`을 산정한다. 장시간 실행을 실제 30초에 끝난다고 약속하지 않는다. 한 대에서 개발과 GPU 캠페인을 동시에 돌리면 성능 평가 부하를 기록한다.

## 9. G1: 정확도를 유지하는 성능 개발

C 신경의 MPS 계산은 이미 구현되어 있다. 새로 해야 할 일은 장치별 증거 공개, 더 넓은 조건의 정확도 확인, 신경·몸·기록·UI 비용에 맞춘 후속 최적화다.

1. CPU 기준, MPS, CUDA의 실행 환경과 실제 장치 사용을 기록한다. CUDA 장비가 없으면 CUDA_REQUIRED gate를 BLOCKED로 남기고 CPU/MPS 결과로 대체하지 않는다. Apple GPU 물리도 신경 MPS와 구분한다.
2. 단일 뉴런 해석해·작은 E/I 회로·불응기·지연·중복 pulse·개입·원시 스파이크·복원으로 수치 계약을 확인한다. 기존 MPS의 v/h/queue 절대 오차 1e-4, rate 1e-3 및 이산 상태 검사를 출발 기준으로 유지하고 실제 배열별 기준을 명시한다.
3. 실제 전뇌 고정 입력과 폐루프를 분리해 비교한다. 발화 임계점 부근의 최초 차이 tick과 원인을 보고한다. 장시간 비선형 궤적에서 서로 다른 하드웨어의 bitwise 일치를 근거 없이 요구하거나 보장하지 않는다. 검토되지 않은 허용 오차 확대도 하지 않는다.
4. `dt=0.1ms`와 더 작은 간격의 비교를 먼저 CPU/선택 회로·고정 입력에서 수행하고 전뇌 표본으로 확장한다. 물리 dt, 신경 dt, 5ms coupling, 화면 갱신 주기를 별개로 관리한다.
5. 구독 없음/8/512, 기록 켬/끔, 집단 변경·취소·복원에서 동역학 불변성을 검사한다. 추가 모니터링 때문에 시뮬레이션 tick을 생략하지 않는다.
6. 시작·컴파일·warmup과 steady-state를 분리하고 같은 checkpoint·조건으로 이전/변경 버전을 교대 최소 5회 측정한다. 중앙값, p95, 최저/최고, 메모리, 처리 모델 시간, 기록량·누락, 시스템 부하를 남긴다.
7. 새 최적화 채택 기준은 수치/물리/기록 검사 통과와 재현 가능한 속도·메모리 이득이다. 최신 로컬 도구 변경의 성능 판정은 변동성이 커 미확정이므로, 과거 개선 배수를 곱해 현재 종합 향상률로 보고하지 않는다.

우선 측정 대상: 희소 이벤트 전파, Metal 버퍼 생성/복사·동기화, 감각 인코더 합산, 몸 접촉·CPG 비용, JSON/바이너리 전송, 과학적 기록 I/O. 신경 state를 GPU에 유지하고 작은 readout만 가져오는 기존 경로를 보존한다.

Apple GPU 물리 계획: 별도 환경에서 현재 MuJoCo 모델을 변형 없이 적재할 수 있는지 재확인 → 미지원 충돌 기능 구현 가능성 조사 → 중력·관절·접촉·외력·복원 동등성 → 단일 장면/다중 장면 별 속도 비교 순서다. 기존 실제 탐색의 plane–mesh margin/gap 오류는 [보존된 결과](../verification/c_remaining_20260909/mjx_explicit_jax_probe.json)로 남긴다. 공식 문서도 MJX-JAX의 단일 장면 성능 불리함을 설명하므로, GPU 이식 자체를 가속 완료로 삼지 않는다. [MuJoCo MJX 공식 문서](https://mujoco.readthedocs.io/en/stable/mjx.html)

## 10. 첫 C 이후의 미구현 확장

### X1. 연결·전달물질·신경 모델의 생물학적 범위 확대

현재 미확정 전달물질 뉴런 19,658개와 신경조절성 뉴런 1,677개의 상태는 계산하지만 해당 출력 효력을 0으로 둔다. 이 정책은 숨겨진 성능 절충이 아니라 공개된 모델 한계다.

- 공식 원자료에서 검증된 전달물질/수용체 근거, 예측값·신뢰도·불일치를 수집한다. 근거가 확보된 연결만 새 weight-model 버전에 반영한다.
- 흥분/억제 부호를 transmitter 하나로 정하는 모델, 세포형별 매개변수, 연결별 지연, 시냅스 동역학을 단계별로 비교한다. DA/SER/OCT에 무조건 +1을 주는 방식은 사용하지 않는다.
- 5개 미만 접촉을 복원하려면 해당 원본 데이터 제품과 snapshot의 접근·출처를 먼저 확보한다. 기존 Codex 필터 자료에서 없던 접촉을 추정해 “원본”으로 채우지 않는다.
- gap junction, 수용체, 구획별 구조, 가소성은 자료가 있는 범위와 없는 범위를 구분한 추가 모델로 만든다. 각 추가 항목의 CPU 기준·GPU 구현·메모리·복원 schema·관측 불변성 검사가 필요하다.
- 원래 프로파일, 검증된 수정, 불확실성 대조의 결과를 분리한다. 전뇌의 masked 비율을 낮추는 것 자체가 자연 행동 성공의 목표는 아니다.

전신 신경계를 먼저 확장할지, 현재 뇌 모델의 감각·출력을 먼저 개선할지는 N1의 병목 결과로 결정한다. 고정 LIF의 한계가 주원인이라는 증거 없이 모든 뉴런을 정밀 모델로 바꾸지 않는다.

### X2. 뇌–VNC–운동뉴런–몸 연결

자료 확보 가능성부터 다시 조사할 수 있다. 조회한 공식 FAQ는 FAFB 뇌 데이터와 **BANC 뇌·신경삭 데이터**를 별도로 제공한다고 설명한다. BANC 존재가 현재 FAFB 코드와 자동 호환되거나 말초·근육까지 완전히 복원됨을 뜻하지 않는다. [FlyWire 데이터 범위](https://codex.flywire.ai/faq)

단계:

1. 같은 표본·성별·snapshot의 뇌와 VNC 연결, 운동뉴런·근육 주석, 누락 범위를 검토한다. 서로 다른 표본의 FAFB와 MANC를 단순 ID/세포형 이름으로 합쳐 실제 전체 신경계라고 부르지 않는다.
2. GraphStore의 고정 FAFB namespace, source schema, manifest, binding·checkpoint 신원을 dataset/specimen/snapshot별로 확장한다. 기존 FAFB 결과와 저장 형식의 재현 경로를 유지한다.
3. 먼저 선택한 다리/관절 회로에서 descending→VNC→운동뉴런→근육/액추에이터 변환과 고유수용성 피드백을 검증한다. 전체 계산기로 확대하기 전에 근육 힘·지연·관절 응답을 확인한다.
4. 이후 전 다리 회로를 통합하고 사전 정의 보행 패턴을 대체한다. 기존 CPG 모드와 신경 회로 모드를 명시적으로 선택하고 기여 대조를 남긴다.
5. 지지·전진·조향·후진·정지·장애물·마찰·외력·복원을 다시 검증한다. 실제 근육 모델 대신 액추에이터 변환이 남으면 그 경계를 공개한다.

이 단계의 일정은 데이터·주석 대응과 근육 연결 근거 확인 후 산정한다. “뉴런을 더 로드하면 완료”되는 작업으로 약속하지 않는다.

### X3. 먹이 섭취·생리 상태·학습

현재 먹이는 냄새원이고 섭식·포만감·대사 모델은 없다. 배고픔/포만감, 섭취, 내부 상태와 감각 변화, 보상·가소성을 각각 상태·입력·기록·복원 계약으로 설계한다. 학습 전후 모델은 가중치·규칙·데이터를 버전으로 고정하고, 학습에 사용하지 않은 과제에서 평가한다. 학습 정책이 커넥톰 대신 정답 방향을 출력하는 구조를 전뇌 고유 행동으로 보고하지 않는다.

### X4. 비행·더 넓은 3D 행동

현재 범위는 3D 물리 안의 바닥 보행이다. 비행은 날개 관절과 힘, 공기역학, 비행 운동 회로, 시각/평형 피드백, 이륙·착륙 과제로 분리한다. 먼저 단일 날개·힘 모델 검증, 고정된 비행 제어 입력에 대한 몸 응답, 신경 연결, 폐루프 안정성 순서로 개발한다. 날개 모델이 없는 몸에 verticalSpeed만 추가하는 것은 비행 구현으로 인정하지 않는다. 벽/경사면 보행도 접착·접촉 모델과 과제 검증을 따로 거친다.
