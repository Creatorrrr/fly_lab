# E182 이후: 남은 네 다리의 실제 시간응답 탐색

E182는 E181에서 중단된 LM plus의3초 평가와 사전 선택된 LM minus 비교를 완료했다. 같은 full BANC/CUDA–FlyBody와 zero 시작을 사용했고, 새 baseline은 기존 raw/신경 상태와 일치했다. LM plus의 이전1.415초 prefix도 그대로 재현됐다. 두 LM 후보 모두 원래 slip 비증가 조건을 넘었으므로 center는 theta0을 유지한다. LF 사전8개 step 불가, LM 두 native 후보 기각을 보존한다. 전체 시간응답 가족이나 신경 회로의 불가능을 입증한 것은 아니다.

다음 E183의 질문은 원래6축 순회 중 미실행 LH→RF→RM→RH가 같은 제한 안에서 실제 보행 지표를 개선하는지다. 새로운 무작위 sweep이나 LM 재조정을 시작하지 않는다. 각 축의 plus/minus는 같은 중심에서 계산하고, 기존 .125/.0625/.03125/.015625 startup backtracking의 첫 적격 값을 각 부호당 한 번만 실행한다. 기존 양수 모집·MN–근육 low/high 합 보존, fixed19, 원래 신경·신체·입력·평가기·startup99·3초 길이는 그대로다. 각 축의 채택 조건은 원래 baseline 대비 forward/net-path95% 이상·slip 비증가·건강성 및 J최소1% 개선, 동일 tie-break다. 축 사이 center만 검증된 선택에 따라 갱신한다. 두 부호 결과와 부모 raw 리뷰 전에 다음 축으로 넘어가지 않는다.

기존 E181/E182 모델 루프와 준비 확인·자원 관측·감독·원자료 검증을 재사용하되 새 실행 범위는 별도 사전 계약으로 명시한다. 기존 gate/실패/원자료를 바꾸거나 가짜 성공 LM 결과를 써서 E181 driver를 재개하지 않는다. 가능한 작은 새 driver에서 고정 과학 계약을 인증한 재사용 함수와 새 네 축 실행 허용 범위를 구분한다. 이 초안은 source 구현이나 gate가 아니며 원본 실행0이다.

남은4축 최대8native 팔과 저장startup 검산, 원본 전 준비 비용까지 기존 누적3911.404136399855/4994초에서 이어 기록한다. 남은1082.595863600145초 안에서 최대1020초를 prospective 예약하는 안을 검토한다. 각 child100/105/110초, 축 driver270/외부285초, CPU1/GPU1·순차 실행, 자동 native 재시도0을 유지한다. 원래13개 native 팔 배정에 대해 E1812회(부분 실패 포함)+E1823회+후속최대8회=13회를 모두 드러낸다. 기준 반복과 실패를 숨기거나 누적을 초기화하지 않는다. 실제 새 계약에서 세부 overhead를 이1020초 내에 맞춰 확정하고 부족하면 launch 전에 줄여 보고한다.

E183에서도 변화가 없어도 F1–F8을 완화하거나 자연 보행을 완료로 표시하지 않는다. 한 번의 순회를 끝낸 뒤에는 동일 grid를 반복하지 않고, 실제 J와 slip·지지/전진 구간의 상충을 근거로 다음 방향을 정한다. 유효한 개선이 있더라도3초 개발 진입 및 최종 동일후보10초/F6/목표 접근·저장·차단/영상이 따로 남는다. 부모 설계→actual gpt-6-sol 난이도별 effort 첫 구현→부모FIRST→같은Sol첫수정→부모SECOND/잔여수정을 유지한다. M2/UI/F6와 원래 finite-goal은 그대로다.
