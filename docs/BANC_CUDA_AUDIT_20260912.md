# BANC CUDA 성능 점검 — 2026-09-12

후속 작업에서 마스크 최적화를 적용하고 10초 보행 재현성을 검증했다. [적용 결과](BANC_CUDA_IMPLEMENTATION_20260912.md)를 참고한다. 아래는 적용 전 점검 기록이다.

BANC는 실제 RTX 4080에서 CUDA Graph와 전용 희소 행렬곱 커널을 사용한다. CUDA 연결은 정상이며, **마스크 곱셈을 뉴런마다 미리 계산하는 후보가 현재 구현보다 행렬곱 1.90배, 전체 세션 1.46배 빨랐다.** 현재 실행 코드에는 적용하지 않았으며, 별도 프로세스의 진단용 시제품으로 검증했다.

## 점검 대상과 현재 CUDA 사용

- 준비된 BANC v888 뉴런 명단 전체: 뉴런 158,706개, 연결 쌍 11,584,852개. `declared_neuronal_roster` 범위이며, 원본 전체 스냅샷의 완전성을 별도로 증명한 것은 아니다.
- 현재 fast 모델: float32, 신경 시간 간격 0.25ms, 결합 RK4 적분, 감각·운동 제어 간격 5ms, 물리 시간 간격 0.1ms.
- 신경 상태·가중치·적분 계수가 모두 `cuda:0`에 유지된다. CPU의 물리·감각·운동 제어와 연결된다.
- 제어 5ms마다 신경 20단계를 CUDA Graph로 한 번 재생한다. RK4이므로 희소 행렬곱은 80회이다.
- 연결마다 뉴런 인덱스와 정확한 float32 가중치 사전 인덱스를 uint32 하나에 담는다. 뉴런당 한 warp의 고정 합산 순서와 `--fmad=false`를 사용한다.
- PyTorch 2.14.0+cu130, CuPy 14.2.0, RTX 4080, 드라이버 591.86을 확인했다. 화면 상단의 CPU 표시는 기본 FlyGym 실험에 해당하며, 별도의 BANC 패널은 CUDA를 사용한다.
- 격리된 모델의 PyTorch 활성 할당은 약 193.6MB였다. 이는 전체 GPU 사용량이 아니다. 희소 텐서의 논리적 `numel`을 실제 밀집 행렬 메모리로 해석하면 안 된다.

현재 모델 해시: `fbd46016a3a294e9f099427aca2e364a343690a6eaf4ec2189fac2c04cf9c3a2`  
그래프 해시: `9bd8468f5e5e40c3e6daaffde9f444466825ba8e69189f1e347568bff85920ff`

## 어디에 시간이 드는가

프로파일러 없이 별도 세션에서 0.15초의 모델 시간을 측정했다. 초기화·워밍업·브라우저 통신은 제외했다.

| 구간 | 전체 벽시계 시간 비중 |
| --- | ---: |
| 신경 계산 | 72.50% |
| 물리 계산 | 20.18% |
| 감각 인코딩 | 4.70% |
| 운동 디코딩 | 1.98% |
| 운동 출력 읽기 | 0.42% |
| 그 외 | 0.22% |

별도의 Nsight Systems 추적으로 제어 5ms를 관찰했다.

| GPU 작업 | 횟수 | GPU 실행 시간 합계 |
| --- | ---: | ---: |
| `csr_current` 희소 행렬곱 | 80 | 26.654ms |
| 원소별 연산 | 1,485 | 2.072ms |
| 축약·인덱싱 | 3 | 0.011ms |
| 메모리 복사 | 6 | 0.031ms |

희소 행렬곱이 **GPU 커널 실행 시간의 92.75%**를 차지했다. 작은 커널이 많지만 CUDA Graph가 이미 CPU 제출 비용을 줄이고 있으므로 행렬곱 개선이 우선이다. `cudaStreamSynchronize`의 26.68ms는 대부분 GPU 계산 완료를 기다린 시간이다. 이를 별도의 제거 가능한 비용으로 더해서는 안 된다. 프로파일러가 붙은 시간과 일반 실행 시간도 직접 합산하지 않는다.

## 후보 비교

같은 전체 그래프와 float32 값으로 CUDA 이벤트 시간을 측정했다. 워밍업 후 80회 행렬곱을 그래프로 재생하고, 순서를 번갈아 7회 비교했다. 사전 마스크 계산 후보와 cuSPARSE의 시간에는 마스크 곱셈 비용도 포함된다.

| 후보 | 행렬곱 1회 중앙값 | 현재 대비 속도 | 수치 비교 |
| --- | ---: | ---: | --- |
| 현재 packed, block 256 | 0.3351ms | 1.00배 | 기준 |
| **packed + 마스크 사전 계산** | **0.1759ms** | **1.90배** | 저장 상태·무작위 입력과 차단 마스크에서 비트 일치 |
| cuSPARSE CSR ALG2 + preprocess | 0.1867ms | 1.79배 | 반복 출력은 일치하나 현재 구현과 차이 발생 |
| cuSPARSE CSR ALG1 + preprocess | 0.1775ms | 1.89배 | 반복 실행에서도 비트 차이 발생 |
| packed, block 64 / 128 / 512 | 0.3471 / 0.3409 / 0.3390ms | 0.97 / 0.98 / 0.99배 | 현재 구현과 비트 일치 |

현재 커널은 각 연결마다 `weight * (rate[column] * mask[column])`를 계산한다. 후보는 RK4의 **각 단계마다** `masked_rate = rate * mask`를 뉴런별로 한 번 계산한 뒤 기존 커널에서 읽는다. 1,158만 연결에서 반복하는 마스크 접근과 곱셈을 약 15.9만 뉴런 단위로 옮긴다. 연결·가중치·뉴런 수·시간 간격·합산 순서는 유지한다. 마스크는 그대로여도 rate가 매 단계 변하므로 제어 간격당 한 번만 계산해서는 안 된다.

cuSPARSE ALG2의 현재 출력 대비 최대 절대 차이는 저장 입력에서 0.001953125, 무작위 입력에서 0.00390625였다. ALG2는 공식 문서상 비전치 연산에서 결정적이지만 기존 커널과 동일한 합산 순서를 보장하지는 않는다. ALG1은 공식 문서도 반복 실행 간 차이 가능성을 명시한다. 따라서 현재 수치 재현성을 유지하면서 더 빠른 사전 마스크 계산을 우선한다. [NVIDIA cuSPARSE 문서](https://docs.nvidia.com/cuda/archive/13.0.0/cusparse/index.html#cusparsespmv)

## 전체 세션 검증

같은 저장 상태에서 현재 구현과 시제품을 각각 복원하고, 0.05초 워밍업 후 다시 시작 상태로 되돌려 0.15초를 진행했다. 신경·감각·운동·물리·진단 처리를 포함한 구간을 순서를 번갈아 5쌍 측정했다. 기본 실험과 BANC 화면이 모두 정지한 상태임을 측정 전후 확인했다.

| 항목 | 현재 구현 | 사전 마스크 시제품 |
| --- | ---: | ---: |
| 모델 0.15초 처리 벽시계 시간 중앙값 | 1.1929초 | 0.8149초 |
| 모델 시간 / 벽시계 시간 | 0.1257 | 0.1841 |

전체 속도는 **1.464배**, 처리 시간은 **31.7% 감소**했다. 비교한 신경 rate·adaptation·drive·mask, 운동 어댑터 상태, 신체 적분 상태의 최대 절대 차이는 모두 0이었다. 현재 모델의 시간 간격을 다시 늘리거나 신경을 제거한 결과가 아니다.

이는 한 저장 상태에서의 짧은 구간 검증이다. 장시간 보행·여러 저장 상태·차단 실험 전체의 검증을 대신하지 않는다. 초기화, CUDA Graph 캡처, 웹소켓·브라우저 지연을 포함한 사용자 화면 성능도 이 수치와 다를 수 있다. 개선 후에도 이 측정의 모델 진행 속도는 실시간의 약 18.4%다.

## 추천 순서

1. **마스크 사전 계산 적용.** 측정한 후보 중 가장 빠르며 기존 수치를 보존했다. 적용 시 차단 마스크 갱신, 체크포인트 복원, 전체 신경·신체 상태 일치 검사를 유지하고 기존 10초 보행 및 인과적 차단 검증을 다시 수행한다.
2. **RK4 원소별 연산을 합치는 커널 검토.** 그래프 노드와 임시 버퍼를 줄일 여지는 있다. 다만 기존 GPU 커널 시간에서 약 7%였으므로 이 부분만으로 큰 전체 가속을 기대하면 안 된다. PyTorch의 반올림·연산 순서를 보존하는지 검증해야 한다.
3. **사전 마스크 적용 후 재측정하여 물리·감각 처리 개선 여부 결정.** 현재 CPU 물리도 전체의 약 20%다. 다른 병목을 무시하고 CUDA만 최적화하면 전체 속도 향상에 한계가 있다. 단일 개체 물리를 GPU로 옮기는 효과는 별도 비교가 필요하다.

블록 크기만 변경하는 방법은 이번 비교에서 개선되지 않았다. cuSPARSE ALG2는 향후 행렬 구조가 달라질 때 비교 대상으로 남길 수 있으나, 현재는 사전 마스크 후보보다 느리고 수치 차이가 있다. VRAM 증설, Tensor Core 활성화, FP16 전환을 이번 문제의 첫 해결책으로 추천하지 않는다. 이 연산은 불규칙한 희소 행렬-벡터 곱이고, cuSPARSELt의 Tensor Core 경로는 지정된 구조적 희소성의 행렬-행렬 곱을 대상으로 한다. [NVIDIA cuSPARSELt 문서](https://docs.nvidia.com/cuda/cusparselt/index.html)

## 증거와 측정 한계

원본 결과는 `verification/banc-cuda-audit-20260912/`에 보존했다.

- `stages-01/profile.json`: 현재 전체 처리 단계별 시간.
- `timeline-01.nsys-rep`, `timeline-01.sqlite`, `timeline-summary.json`: 실제 CUDA API·커널·복사 추적.
- `timeline-worker-01/metadata.json`: GPU 버퍼, CUDA Graph, 커널 설정, 소스 해시.
- `spmv-04/result.json`: 채택한 7회 커널 비교와 수치 검증.
- `premask-session-02/result.json`: 채택한 5쌍 전체 세션 비교와 상태 오차.
- `spmv-01`, `spmv-02`: cuSPARSE DLL·그래프 캡처 통합 문제로 중단한 진단 실행. 성공 결과로 집계하지 않았다.
- `spmv-03`: 화면 실행과 겹친 시간은 비교에서 제외했다.
- `premask-session-01`: 측정 후 기본 화면이 실행 중이어서 간섭 시점을 확정할 수 없었다. 성능 결론에는 다시 측정한 `premask-session-02`를 사용했다.
- `ncu-status.json`: Nsight Compute는 두 번 모두 종료 코드 1로 보고서를 남기지 않았다. 정확한 원인은 확인하지 못했다. **SM 점유율이나 메모리 대역폭 포화는 측정하지 못했으므로 단정하지 않는다.**

추가한 진단 도구 3개의 Ruff 검사와 포맷 검사는 통과했다. 기존 실행 코드, 설정, 모델은 변경하지 않았다. 최종 비교를 위해 멈춘 기본 실험은 이어서 재생했고, 사용자가 새로 선택한 BANC 8.75초의 정지 상태는 유지했다.
