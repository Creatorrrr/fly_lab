**설계가 해결해야 할 확인된 차이**

- `flylab/c/flybody_flight.py`의 자체 과제는 행동 66차원, 공식 기본 `flight_imitation()`은 12차원이다. 단순 0 채우기나 배열 재배열만으로 정책 호환성을 주장하지 않는다.
- 기존 C 제어 간격은 5 ms이며, 원본 비행은 정책 200 µs/물리 50 µs다. 5 ms 묶음 하나에 정책 25회와 물리 100회가 필요하다.
- `CEngine.step()`은 보행용 센서/모터/몸·시간 계약에 연결되어 있다. 기존 전역 `CONTROL_DT`를 바꾸어 비행에 맞추면 신경·체크포인트·보행의 의미도 바뀐다.
- `common.py`는 물리 mm/z-up과 UI mm/y-up을 변환한다. 원본 FlyBody cm/z-up에서는 길이·속도에 x10을 먼저 적용해야 한다. 방향·쿼터니언 변환은 위치 배열처럼 처리하지 말고 회전행렬의 기저 변환으로 검증한다. 토크·관성 등의 내부 물리 값은 원본 단위로 유지하는 설계가 초기 위험을 줄인다.
- `StateStore`는 저장 형식을 제공하지만 Composer, WPG, 관측 버퍼, RNG, 정책 상태를 자동으로 수집하지 않는다. MuJoCo 배열만 저장해서 미래 궤적의 재현성을 주장할 수 없다.
- 도식적 웹 날개는 고정 좌표다. 네이티브 메시 관찰과 웹 날개 표시를 별도로 연결해야 한다.
- 원본 소스의 optional TF 의존성은 TensorFlow 2.8.0, TensorFlow Probability 0.16.0 등이고 core NumPy는 1.26.4로 명시되어 있다. 현재 FlyLab 환경에 바로 설치하는 것은 피하고 실제 로딩/추론이 가능한 격리 환경을 먼저 확인한다. Windows 네이티브 또는 WSL의 채택 여부는 아직 검증하지 않았다.

**인터페이스와 실행 순서 초안**

`FlightSession`은 create/reset, advance(정수 control count), set_command, observe, snapshot/restore, close를 소유한다. 구체적인 모듈 경로와 메서드 이름은 GPT Pro 검토 후 확정한다. UI용 상태에는 session ID, epoch/sequence, physics tick, policy tick, sim time, 모델/정책/패턴/환경 해시, 몸 위치·쿼터니언·속도, 날개 6축, 접촉/실패 상태, 명령 출처가 필요하다. 물리 값과 표시용 값의 단위는 각각 표기한다.

한 5 ms 묶음 안에서는 200 µs마다 관측→정책→WPG 보정→날개 구동→4회 물리 적분 순서를 원본 환경과 동일하게 실행한다. 상위 목표는 묶음 시작의 명령 버전으로 고정하되, 정책의 고유 감각 갱신은 매 200 µs 수행한다. 통신을 위해 같은 행동을 5 ms 동안 붙잡아 두는 방식은 원본 정책 실행과 같지 않다. 벽시계 성능이 느려져도 물리 스텝을 건너뛰지 않고 화면 진행 속도를 낮춘다.

고속 날갯짓은 낮은 FPS에서 정지·역회전처럼 보일 수 있다. 정상 속도와 관찰용 slow motion의 표시 시간을 구분하고, 느린 화면을 만들기 위해 실제 날갯짓 주파수를 바꾸지 않는다. 날개 관절 고주파 기록에서 프레임을 선택하거나 같은 물리 상태 복제본을 렌더한다. 관찰 영상을 다시 비행 제어 입력으로 사용하지 않는다.

**채택 기준을 정하는 방법**

| 평가 대상 | 필요한 성공 증거 | 성공으로 취급하지 않을 것 |
|---|---|---|
| 공식 기준 비행 | 사전 고정한 참조 궤적 집합의 전체 구간을 완료하고 위치·자세 오차/실패율을 보고. 공식 환경 기준과 차이 정량화 | 학습 패턴 없이 prototype가 잠시 뜨는 현상 |
| 지속 비행 | 고도·속도·자세 허용 범위의 연속 유지, 충돌 없음, 여러 초기 조건에서 반복 | 마지막 프레임 하나의 성공, 일시적 목표 통과 |
| 조향·시각 비행 | 목표 도달/회피 성공률, 경로·고도 오차, 접촉·시각 입력 차단 대조 | root 위치 주입이나 목표 방향의 감각 위장 |

지속 시간, 거리·각도·충격 임계값은 F1의 기준 환경 결과와 과제 정의를 바탕으로 사전에 고정한다. 논문의 수치를 현재 Windows 포트의 검증 완료 기준으로 복사하지 않는다. 비용과 처리율은 짧은 실제 실행을 측정한 뒤 산정하며, 현재 단계에서 실시간 구동이나 학습 소요 시간을 보장하지 않는다.

**GPT Pro 응답을 받은 뒤 마무리할 작업**

외부 분석의 핵심 주장과 경로/심벌 인용을 준비한 스냅샷과 대조하고, 현재 파일이 달라졌으면 해당 해시 차이를 기록한다. 확인되지 않은 추천은 가정으로 남긴다. 아키텍처 비교와 F0~F7을 수정한 최종 계획, 채택/기각한 의견과 이유, 남은 검증 항목을 별도 문서로 정리한다. 외부 답변이 첨부 ZIP을 실제로 읽지 못했다면 코드 분석 완료로 취급하지 않는다.
