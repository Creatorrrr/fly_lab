# E113: 밀집 발 궤적 보정의 실제 BANC·신체 전달 검사

## 질문과 고정 후보

E112b는 유효한 조건부 보정으로 부모의 독립129개 검사를 통과했다. 원래99 및 내부 초기 여유는 통과했지만 발 위치 개선3.949%·속도 개선9.376%가 사전20%에 못 미쳤고 q오차는1.408% 증가했다. 따라서 local_supported=false와 과거 실패는 유지한다. 한편 실제 E110은 F3 전진을 통과해도 연속 전진 구간이 다리 주기보다 짧아 완전 전진 주기가0이었다. E113의 별도 질문은 **같은 원래 자세에서 E112b의 초기 안정성 여유와 개선된 발 전환 속도가 실제 연속 보행을 개선하는가**이다. 조건부 개선을 실제 개선으로 가정하지 않는다.

후보는 e112-dense-foot-recruitment-v2의 선택된 float32 가중치 그대로다. 그래프158706/원래 CSR·연결 부호·49입력·391MN·96근육·38개 tau·rest/moment/pool/신체/감각을 유지한다. E110 대비 변경은 기존1572개 source-to-MN 시냅스 효능과 그 기록값 두 필드뿐이다. 모든 신경 상태는 원래 E32의 전체0 중립에서 시작한다. 준비 중 실제 그래프 전체 가중치와 원래 전체 tau를 검사한다. 조건부 입력, 위상, 교사, 시간 궤적, root/pose 보정 또는 새로운 런타임 동역학은 넣지 않는다.

부모는 모델을 만들지 않고 부모 독립 입력 parent-e113-expected-calibration.npz 및 parent-e113-expected-observation.npz를 만들었다. 전체 입력 명세 parent-e113-expected-inputs.json SHA256은 `96789069a39aaf4192becc0b4491c465a871691ca89bfd0de00509c04026984a`다. 59개 원래 E112b 출력의 해시와 원래 부모 리뷰를 재확인한다. parent-output-manifest.json은 원래 fit 산출물만 담으며, 최초 부모 리뷰 도중 쓰인 부모 stdout/stderr 두 개는 원래 fit 입력으로 사용하지 않는다. 원래 리뷰와 이 구분을 모두 보존한다. calibration edge_ids는 정렬되지 않았으므로 명시적 ID 매핑을 사용한다.

## 한 번의 실제 검사

검증된 E110 실행 경로를 기준으로 E113 전용 실행기와 테스트를 작성한다. 기존 도구와 평가기·M2·제품 파일은 수정하지 않는다. 원래 E32 전체 중립, 같은 arena/신체/입력, 실제 CUDA 신경 계산, 실제 신체 감각 피드백을 사용한다. main10초=2000개5ms control이며 신경250us·물리100us 간격을 유지한다. 1초의 전체 저장 상태를 clone하여0.1초 전진하고 main1.1초와 전체 상태를 bitexact 대조한다. 최대 실제 비용은 신경10.1초/물리10.1초다. F6 두 새 초기 자세는 노출하지 않는다.

442 basic/446 detailed/55 metadata ID와 순서는 부모 관측 fixture와 같아야 한다. raw control/신경 rate·current·drive·adaptation/96 activation/native 발 하중·접촉·slip/실제 clock 및 부분 실패를 분석보다 먼저 저장한다. 원래100us native health guard(비발접촉0, upright>=.9, 유한 신체·신경, fault0)를 유지한다. 모든 생성/restore/저장/clone/후처리 실패에서 소유한 세션을 닫고 원래 오류와 실제 진행된 신경/물리 시간을 보존한다. 관측 목적으로 live 신체 상태를 변경하지 않는다.

원래 F3–F5 평가 코드와 창[.5,10), 고정 초기방향 전진>=10mm·순이동/경로>=.5, 다리별 전진 적격 완전주기>=10, 좌우 반주기±.15/R>=.5, 네 무릎 LF25/RF30/LH40/RH35도, 여섯 주기CV<=.3을 그대로 쓴다. 실제 전진속도20ms Gaussian, >.5mm/s·연속구간>=.3초 및 주기 전체 포함 규칙을 바꾸지 않는다. E110의 같은 창 결과와 supported load-weighted slip1.9571845276606095mm/s를 비교한다. 새 후보의 실제 source 위상 지표는 물리 지표와 별도다.

초기99 (.005–.495초)의 실제 q/LTM과 E112b 조건부 예측 오차(RMS<=.002, max<=.01)를 별도 검사한다. 원래 E100/E10399 조건(qRMS.02/qmax.05/LTMRMS.01/LTMmax.03)을 그대로 보고한다. 새 내부 여유의 기대 효과는 이 실제 전달 검사에서 확인하며, 실패를 숨기거나 시작 상태를 맞추기 위해 reset하지 않는다. 물리적 안전 정지는 원래 native health/resource 규칙을 따른다. 현재의 conditional shape 실패는 실제 지표가 좋아져도 소급 변경하지 않는다. F3–F5를 전부 통과하더라도 전체 F1–F8 완료나 생물학적 기전 검증 완료가 아니다.

## 자원·개발·리뷰 순서

이전 실험들의 보수 합449.4057126초를450초로 올림 계상한다. E112의 원래 한도506초와 그 결과는 유지하며, 별도 실제 전달 질문 E113에 준비<=40초/신체 및 후처리<=140초/외부프로세스<=180초를 사전에 배정한다. E113 공유 상한은450+180=630초다. 실행 준비·정리까지 외부 감독 receipt를 기록하고 자동 재시도하지 않는다. 모든 raw/cost/오류는 새 e113-dense-foot-native-body/에 보존한다. 이 단계에서 fit/새 근사 신경 계산/임의 재학습은0이다.

부모가 이 설계와 독립 fixture를 소유하고, 기존 명시적 gpt-5.6-sol xhigh가 tools/verify_c_banc_m3_e113_body.py 및 tests/test_c_banc_m3_e113_body.py만 개발한다. native 전체 상태·GPU·신체 clock/cleanup의 난도에 맞춰 xhigh를 사용한다. 먼저 모델 없는 테스트와 소스만 작성하며 실제 실행은 금지한다. 부모 첫 리뷰→필요한 첫 수정은 같은 Sol→부모 재리뷰→남은 수정은 부모 순서를 따른다. 부모 최종 소스 검토 이후 단 한 번의 실제 실행을 허용한다. 사용자의 기존 전체 개발 승인을 따르며 별도 사용자 확인을 반복하지 않는다.
