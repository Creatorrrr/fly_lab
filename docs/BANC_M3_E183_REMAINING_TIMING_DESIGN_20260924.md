# E183: 남은 네 다리 시간응답의 한 번 순회

E182의 실제 기준/LM 두 팔은 완료됐고 두 후보는 native slip 비증가를 위반했다. 기준은 기존 E181 raw와 재현됐으며 center는 theta0이다. E181의 LF startup 8개 기각, LM partial 실패 및 E182 재검증 비용을 유지한다. 이번 질문은 아직 실행하지 않은 LH/RF/RM/RH 모집 시간응답을 바꾸면 같은 보호 조건 아래 지속 전진의 진입 조건을 개선하는가다. 시간응답을 바꿔도 slip 또는 startup과 상충하거나 연속 보행이 생기지 않는다는 경쟁 설명을 함께 평가한다.

고정 과학 계약은 E181과 같다. 신경/신체/입력/158706 BANC CUDA/391MN/96근육/42명령/3초/초기 상태/평가기/fixed19/tau/kappa/해부학적 membership은 변경하지 않는다. 기존 양수 common/low-only/high-only bank의 시간별 재배분만 수행하고 low/high 합을 보존한다. 외부 위상, 궤적, CPG, root 교정은 추가하지 않는다. J는 [0.5,3) 실제 전진속도의 0.5mm/s 부족 평균이다. 건강성, 원래 baseline 대비 전진/net-path 95%, native slip 비증가와 startup RMS .02rad/max .04rad를 유지한다. 중심 J 대비 max(1e-6,1%) 개선, J→theta 제곱합→plus 우선 tie-break도 그대로다.

LH→RF→RM→RH를 각 한 번 수행한다. 각 축의 plus/minus는 같은 부모 검토된 중심에서 `.125,.0625,.03125,.015625`의 첫 startup 적격 step만 각각 최대 한 번 native 실행한다. 둘 다 저장 startup에서 부적격이면 native 없이 결과를 보존한다. 양쪽 결과와 부모 원자료 검산 후에만 다음 축을 허용한다. center는 그 선택으로만 갱신하고, 처음에는 theta0/E182 baseline이다. 이미 끝난 LF/LM을 다시 찾거나 두 번째 순회를 하지 않는다. 개발 진입은 전진 구간 .3초 이상과 다리마다 최소 1완전주기이며, 개선된 J만으로 진입 또는 최종 F3–F5를 인정하지 않는다.

구현은 `tools/continue_c_banc_m3_native_timing.py`와 `tests/test_c_banc_native_timing_continuation.py` 두 파일이다. 기존 E181/E182 파일은 불변이다. E181의 `propose_axis`, `preflight_direction`, `_saved_startup_callback`, `select_axis`, `run_arm`, `supervise_command`, `_attempt_accounting`을 재사용하고 E182 readiness/resource monitor를 재사용한다. 새 driver는 `--axis lh|rf|rm|rh`로 한 축만 처리한다. 기존 `verified_inputs`는 진짜 E181 freeze/source/baseline/LF 리뷰로 `mode=lm`을 검증한다. 이것은 고정 과학 함수/입력의 인증일 뿐 새 축 순서의 허가가 아니다. E183 freeze/source gate가 별도로 남은 네 축과 theta/중심/전임 결과/부모 리뷰를 검증한다. 가짜 E181 LM 성공 결과나 monkeypatch로 gate를 우회하지 않는다. raw의 E181 identity는 그대로이고 별도 E183 provenance가 실제 축·부호·중심·request·freeze/source/result 해시를 연결한다.

E183 freeze에는 design/source ownership, immutable E181/E182 gate 및 E182 최종 판정/전체 기준 raw 해시, 축 순서·step·자원·출력 범위를 담는다. 새 source review는 부모가 현재 구현을 읽고 검증한 후 생성한다. 후속 축은 직전 축의 정확한 result 해시와 부모 raw 해시/선택 검산 리뷰를 요구한다. 전체 raw 파일 inventory를 검증하고 안전한 상대 경로/중첩 체크포인트를 허용하되 경로 이탈과 symlink를 거부한다. 부모 검토는 새 science helper를 재작성하지 않고 원자료에서 독립 J/물리·모든 변경축의 scalar tilt·bank/activation/q/clock/CUDA/초기 동일성을 확인한다.

원본은 별도 프로세스 최대8회, 각3모델초/12000신경/30000물리 단계다. 기존 E1812회(부분 실패 포함)+E1823회+후속 최대8회=13 native 시도로 가족 전체를 기록한다. 새 baseline 반복은 없다. 기존 누적3911.404136399855/4994초에서 E183 최대1020초를 사전 예약한다. native 감독 최대8*110초와 최대140초의 준비·저장 startup·import/검증 여유를 포함한다. 이전 비용과 이번 실패/중단 준비 비용을 초기화하지 않는다. 각 축 driver270초/외부285초, child100/105/110초, CPU1/GPU1, 디스크 free20GiB/arm1GiB/campaign4GiB, 자동 재시도0이다. 모든 실제 native 감독 시간과 native 외 driver 경과를 중복 없이 합산하고 미완료/알 수 없는 시도는 상한으로 예약한다. 다음 launch 전에 현재 경과·다음110초·누적/축 cap을 확인한다. 하드 한도를 초과할 수 있으면 native를 시작하지 않는다.

한 축 output은 create-only이며 중단된 축도 raw와 terminal driver result/비용을 보존한다. 다른 축으로 진행하기 전에 부모가 실제 프로세스 종료를 확인한다. child는 정확한 frozen request와 실제 살아 있는 driver 조상을 검증한다. 요청된 theta는 intent의 저장 startup 선택 및 좌표 연산과 일치해야 한다. child 자신의 이미 허용된 intent/request를 재실행으로 오인하는 E182 FIRST 오류를 반복하지 않는다. 각 native 전 2초 간격 두 live queue/PID readiness 관측을 하고, 실행 중 queue counts/GPU 상태만 약2초 간격 기록한다. 타 작업 내용 조회/종료/변경은 없다. readiness 불명/경합은 새 native를 막고 사실대로 기록한다.

부모 설계→실제 `gpt-6-sol/high` 최초 구현→부모 FIRST 리뷰→같은 Sol 첫 수정→부모 SECOND→남은 수정은 부모 순서를 사용한다. 소유 두 파일의 합성 테스트·lint, 가능한 실제 설치 API 경계 확인 후에 원본을 실행한다. 합성 테스트는 의미 있는 요청/순서/center/중단 accounting 회귀에 한정한다. 원본 실행은 부모만 수행한다. 결과는 유효성, 후보 선택, 개발 진입, 전체 목표 완료를 구분한다. 전 축이 유효하게 기각되면 같은 grid를 반복하지 않고 실제 J/slip/startup/반복성 상충을 근거로 다음 방법을 설계한다. 유효 개선이 있어도 같은 후보 최종10초/F6/F7/F8은 별도 미완료다.
