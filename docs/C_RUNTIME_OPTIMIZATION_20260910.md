# C 실행 최적화 · 2026-09-10

현재 C_STRICT/MPS 경로의 반복 복사·할당·Python 제어 비용을 줄이고, 브라우저의 계산 요청을 화면 렌더링 주기에서 분리했다. 변경 직전 소스와 비교한 5개 조건의 계산 시간은 중앙값 기준 **9.7–13.0% 감소**했다. 아래 수치는 이번 변경의 추가 효과이며, 과거 CPU 대비 MPS 배수를 곱한 값이 아니다.

## 적용한 변경

| 경로 | 변경 | 보존한 동작 |
|---|---|---|
| MPS | pulse 대상의 안정 정렬·CSR 포인터, 개입 마스크, 입력·관측 버퍼, 커널 호출 객체 재사용 | 중복 pulse의 덧셈 순서, 입력 검증, CPU 입력 소유권, 복원 시 캐시 무효화 |
| BANC | 5ms마다 만드는 롤백 스냅샷에서 불변 진단 기록 참조 재사용, 감각 차단 채널 캐시 | 상태 배열은 복사, 외부 체크포인트는 완전한 독립 복사, 입력 거절 시 원래 상태 복원 |
| FAFB 몸 | 여섯 다리의 반사·관절 목표 계산을 Numba로 묶고, 한 제어 구간 동안 고정되는 하행 입력 설정을 한 번만 실행 | float64, fastmath=False, 기존 CPG·접촉·보간 연산 순서 |
| 브라우저 | 응답이 끝나면 다음 계산을 예약하며 약 40ms 응답 목표로 1–10개 제어 구간을 조절 | 동시 요청 하나, 일시정지·숨김·연결 종료·오류 시 추가 예약 중지 |

물리·신경 적분은 계속 0.1ms, 감각·운동 제어는 5ms다. `lif.metal`, `observation.metal`, 모델·바인딩·충돌 설정은 변경하지 않았다. GPU 신경 계산과 CPU 몸 계산의 기존 인과적 겹침 실행도 유지한다. 브라우저의 40ms는 묶음 크기를 고르는 목표이며 응답 지연의 상한 보장은 아니다.

초기 구현에서 Numba의 `np.interp`가 기존 NumPy와 마지막 비트에서 달라져 정확 일치 검사가 실패했다. 보간은 원래 NumPy 구현으로 유지한 뒤 다시 통과했다. 실패 로그도 [원자료](../verification/c_runtime_opt_20260910/physical_initial_tests.log)에 보존했다.

## 변경 전후 측정

변경 직전 커밋 `a16e4f3b7c7207db0bcc1174df7edc7aa5e9aede`의 깨끗한 소스를 [동결](../verification/c_runtime_opt_20260910/baseline_identity.json)했다. M1 Max 32GB, macOS 26.6.2, Python 3.12.7, PyTorch 2.14.0, MuJoCo 3.9.0, FlyGym 2.1.0에서 동일 체크포인트를 별도 프로세스로 복원했다. 각 조건·버전마다 0.3모델초씩 3회, 실행 순서를 교대했다.

측정에는 두 제어 구간마다 `CEngine.step(2)`, 프레임 생성, JSON·바이너리 신호 인코딩을 포함했다. 초기화·JIT 예열, 기록 시작·종료와 체크포인트 내보내기, 네트워크·브라우저 렌더링은 제외했다. 다음 표는 3회 벽시계 중앙값이다.

[모든 반복값과 정확 일치 판정](../verification/c_runtime_opt_20260910/benchmark_final/report_rechecked.json), [비교 도구](../verification/c_runtime_opt_20260910/compare.py), [최적화 소스 체크섬](../verification/c_runtime_opt_20260910/modified_source_sha256.json)을 보존했다. FAFB/BANC 현재 상태는 각각 0.050모델초, 직접 자극 보행 상태는 별도 대조 실험의 5.000모델초 체크포인트에서 시작했다. 직접 자극을 사용자 실험에 넣지 않았다.

**30회 모두** 최종 체크포인트 전체, 프레임의 계산 결과, 신호 바이너리가 변경 전 결과와 정확히 일치했다. 기록 조건의 발화·운동 이벤트, 몸 표본, 전압·발화율 배열도 일치했고 기록 누락은 0이었다. 비교에서 제외한 것은 프레임의 측정 시간과 실행별 기록 저장 경로다. 최초 비교기는 절대 경로만 정규화해 상대 경로 60곳을 차이로 표시했다. [최초 결과](../verification/c_runtime_opt_20260910/benchmark_final/report.json)를 유지하고, 저장된 동일 원자료를 [경로만 정규화해 재검사](../verification/c_runtime_opt_20260910/recheck.py)했다. 측정값이나 계산 상태를 바꾸거나 다시 골라 측정하지 않았다.

일반 데스크톱의 다른 작업을 중단하지 않은 짧은 측정이므로 편차가 있다. 예를 들어 BANC 기록 조건은 변경 전 0.969–1.192초, 변경 후 0.877–0.999초였다. 장시간 처리율이나 개별 실행에서 같은 개선율을 보장하지 않는다. 위 표는 브라우저 예약 개선의 별도 배수를 산출한 결과가 아니다.

## 검증과 실행 서버

- [전체 회귀 검사](../verification/c_runtime_opt_20260910/regression.log): **257/257 통과**, 건너뜀 0. 실제 MPS 수치·입력 소유권·버퍼 재사용·복원, BANC 입력 거절 후 롤백, 원래 몸 제어기와의 정확 일치 포함.
- [브라우저 예약 단위 검사](../verification/c_runtime_opt_20260910/playback_tests.log): **6/6 통과**. 화면 프레임 없이 계속 계산, 묶음 제한, 중복 요청 방지, 정지·숨김·오류 처리.
- [실제 MuJoCo 물리 검사](../verification/c_runtime_opt_20260910/physics_gate.json): **14/14 통과**. 3모델초 보행, 접촉·외력·운동 차단·복원 후 연속 계산. 복원 적분 상태 최대 차이 0. 이 검사는 기존 B 제어기의 물리 경로 검사이며 BANC 보행 성공 판정이 아니다.
- [실제 브라우저 검증](../verification/c_runtime_opt_20260910/live_verification.json): FAFB 0.050→1.850초, BANC 0.050→2.475초 재생·일시정지, 정지 후 1초간 시각 유지, 경고·오류 로그 0건. FAFB의 실제 이동·장면 표시를 확인했다. 표시된 계산 배속은 각각 0.259·0.310이며 브라우저 전체 성능 비교값은 아니다.

현재 서버는 [FAFB :8774](http://127.0.0.1:8774), [BANC :8775](http://127.0.0.1:8775)다. 두 실험을 `before-runtime-opt-20260910`으로 저장하고 같은 포트의 서버만 재시작했다. 브라우저 검증 뒤 모두 원래 **0.050모델초·C_STRICT·MPS·일시정지** 상태로 복원했다. `after-runtime-opt-20260910` 체크포인트를 대조해 구독 epoch의 의도된 증가를 제외한 모든 상태가 정확히 일치함을 확인했다. 응답 HTML도 새 빌드와 동일하다. 이전 :8772/:8773 서버는 이 작업에서 갱신하지 않았다.

실시간보다 여전히 느리다. CPU MuJoCo 물리와 0.1ms마다 순차 실행하는 신경 커널 비용이 남아 있다. BANC의 낮은 보행 속도는 이번 계산 최적화로 해결했다고 판정하지 않는다. GPU 물리 전환이나 장시간 자연 탐색 캠페인은 이번 검증 범위에 포함하지 않았다.
