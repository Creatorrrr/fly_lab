# E162 RM proximal 효능 대조: 채택하지 않음

RM group70의 효능을 5.582673% 줄인 대조에서 지속 보행은 개선되지 않았다. 시작 양립성 및 10초 물리 건강성은 만족했지만, 전진 중단·미끄러짐·RM 제동의 개발 진입 조건을 충족하지 못했다. 원본 실행은 마지막 판정의 NumPy 불리언 JSON 저장 오류로 기술 실패 상태를 유지한다. 아래 물리 수치는 보존된 완전한 원시자료를 부모가 별도로 검산한 결과이며, 원본을 성공으로 다시 표시한 것이 아니다.

## 설계와 실제 실행

[고정 설계](BANC_M3_E162_PROXIMAL_UNLOAD_DESIGN_20260922.md)에 따라 E150의 저장된 신경 출력에서 RM trochanter extensor group70 하나의 효능만 줄였다. 나머지95개 근육의 활성, LTM, 신체·지면·제어 및 물리 dt는 유지했다. 복원 관측인 tick0의 명령은 그대로 보존했다. 이는 저장 신경 출력의 신체 대조다. 전체 BANC 감각 폐루프의 변경이나 생물학적 기전 검증은 아니다.

원래99 시작 표본의 q RMS≤.02/max≤.04를 만족하는 해석적 교차구간에서 λ=.055826732202023964, 효능 배율 g=.9441732677979761을 한 번 계산했다. 활성 제약은 원래99 배열의 [58,32], 즉 control59/.295초의 RM femur-pitch 최대 오차다. 양의 상한에는 설계의 고정 수치 여유를 적용했다. 시작 q RMS=.01784598422674095, max=.03999999999997994로 통과했다. LTM은 변경하지 않았으며 기존 오차 RMS=.001363757229768329/max=.01319080027864962였다. 시작 자료는 선택에 사용된 개발 자료이고 독립 확인이 아니다. F6 초기 자세는 노출하지 않았다.

원본 process1회, 자동재시도0, 신체1/shadow1, 준비2000 및 scientific100000 물리 단계, shadow forward100000회를 기록했다. 추가 신경 계산·fit은0이다. 실제 CPU1/GPU0의 저장 명령 대조이며 CUDA 신경 실행 검증으로 세지 않는다. 프로세스는 종료됐고 감독 시간106.057297초, 보수 연속 누적2767.057297/사전2956초였다.

## Sol effort와 리뷰, 발견한 오류

부모 설계 → 실제 gpt-5.6-sol/high 첫 구현 → 부모 첫 리뷰 → 같은 Sol/high 첫 수정 → 부모 두 번째 리뷰/잔여 수정 순서를 지켰다. 해석적 제약과 native 물리/실패 기록을 함께 다루므로 high를 사용했다. 생성 자료의 단순 분석은 medium, 기계적 변경은 low, 새로운 신경·CUDA·상태 아키텍처는 xhigh를 적용하는 기존 정책을 유지한다. 기존 에이전트의 followup이 실제 effort를 변경한다고 기록하지 않는다.

첫 리뷰 R1–R5는 물리 시계 오차, 명령 재구성, RMS 경계 계산, 실패 시 성공 판정 취소, 종료 경로의 해시 확인이었다. 같은 Sol의 첫 수정 후26 tests와 부모의 독립20개 계산 대조가 통과했다. 부모가 R6 중복 해시 읽기와 R7 원래 I/O 오류/임시 증거 보존을 수정했고, 원본 실행 전29 tests/Ruff/format/compile 및 실제 입력 계약 점검이 통과했다.

실제 원본의 물리100000단계와 주요 결과 저장까지 끝난 뒤, longest-bout 비교의 np.bool_를 advancement.json에 저장하면서 TypeError가 발생했다. 검증용 fixture의 Python float가 실제 NumPy 스칼라 경로를 충분히 대표하지 못한 결함이다. 이 원본의 실패 상태·로그·해시는 보존했다. 부모가 판정 경계에서 불리언 스칼라를 native bool로 변환하는 R8을 직접 수정했고, 같은 NumPy 스칼라를 사용하는 전체 생성 pipeline 테스트를 추가해30 tests/Ruff/format을 통과했다. 수정 후 원본 물리를 다시 실행하지 않았다.

원본 실행 소스 SHA는 d26c02ce4744978479c867ff95fa93c9795e12b8ee4fd6002f1416cf0d1e5b7e이고 원본 디렉터리에 해당 소스 snapshot이 있다. R8 이후 현재 소스 SHA는 d176fecae0b7f0f1d0cfd15a9bfff4c1a0a9fb39d25540a87affabf2149bcf71이다. 후자를 원본 실행 소스로 표시하지 않는다.
