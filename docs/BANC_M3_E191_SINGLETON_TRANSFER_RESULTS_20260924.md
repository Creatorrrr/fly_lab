# E191 결과: 입력 출처 혼동으로 적합 전 종료

E191은 `invalid_not_tested`다. 원본 프로세스1회, 적합0회이며 과학적 기각이나 보행 개선 증거가 아니다. `command alias differs`에서 중단되어 유한 후보도 생성하지 않았다. 원형 입력과 오류를 보존했다.

부모 설계 → actual gpt-6-sol/high 구현 → 부모 FIRST → 같은 Sol 첫 수정 → 부모 SECOND 및 잔여 직접 수정 순서를 지켰다. 부모는 첫 수정본에서 빠진 생성+solve20초 제한과 약해진 잔차 기준을 복구했다. 다양한 입력의 소유권/QR/native 검산, 해가 알려진 실제4117변수 SOCP, 게시 실패, 생성 시간 초과를 포함한8개 테스트 및 Ruff/CLI가 통과했지만 실제 출처를 서로 다른 것으로 구성하지 않은 시험에는 부족함이 있었다.

E169 freeze의 `trace`는 E150 실제 보행 기록이고 `startup`은 E103이 저장한 E100 시작 자세 기준이다. 기존 E164 준비 코드는 이 두 전체 recorded 배열의 동일성을 요구하지 않는다. E191의 두 새 별칭 조건은 잘못됐다. 부모는 각각 원래 E150 trace 및 E103 NPZ의 동결된 해시와 exact 배열을 검산했다. 두 기록의 차이는 command max.447834719724516rad, tendon max.013190800278650이지만 손상 증거가 아니다. 그 밖의 E191 입력 검사 조건은 통과했다. 부모 수집형 진단은 적합이나 원본 gate 우회 실행이 아니며, `parent-e191-input-origin-audit.json`에 모든 조건을 보존했다.

원본 감독2.664067900001초를 더한 누적4658.458035699718/4994초, 잔여335.541964300282초다. 부모 원본 종료 검산.3768989초는 candidate 부재를 기록하며 valid=false다. 부모 출처 감사1.1688249초, 최종 생성시험17.6035980초 및 lint/CLI.5009345초는 별도 비용이다. 과거 Sol 생성시험 중 미집계 부분을0으로 두지 않는다. 원본 살아 있는 자식0, M2/UI 불변, F6노출0, 후보 미채택, F1–F8/전체 목표 active·미완료다.

다음 E192는 두 전체 배열의 허위 동일성 조건을 각 원래 출처의 exact 검증으로 대체하는 기술 복구다. 전달 가족, 목표, 물리 보호, 시작 자세와20% 문턱, solver/수치/시간 계약은 E191 그대로 유지한다. E191의 실행 및 동결 소스는 보존하며 별도 설계/소스 검토/한 번의 원본 실행을 사용한다.
